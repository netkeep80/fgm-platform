# S3-S2E — обработка отказов кадра WebGPU

Срез продолжает [ограничение чтения кадров](renderer-session-s3-s2d.md) и проверяет обработку отказов из [план Platform](https://github.com/netkeep80/fgm-platform/issues/15). [FGMV-SESSION-006](../../requirements/renderer/FGMV-SESSION-006.rg.yaml) имеет кандидатный жизненный цикл.

Сессия очищает холст при отказе актуального кадра. `failed / E_SESSION_GPU_FRAME` означает отказ подготовки или выполнения команд, включая ошибки из областей WebGPU. `failed / E_SESSION_GPU_READBACK` означает отказ чтения пикселей при отсутствии наблюдаемой потери устройства. Временные ресурсы освобождаются и после частичного выделения. При сбое живое устройство можно использовать для следующего запроса. Подтверждённое событие `GPUDevice.lost` очищает холст и переводит актуальные запросы к этому устройству в `device-lost`. Управляемое восстановление устройства остаётся отдельным этапом. [Спецификация WebGPU](https://www.w3.org/TR/webgpu/#errors-and-debugging)

Chromium подставляет отказ `mapAsync` и исключение при выделении текстуры после выделения буфера. Отдельно создаётся недопустимая текстура для проверки настоящей ошибки валидации. Тест проверяет прозрачность холста, освобождение частично выделенного ресурса и успешный повтор на том же устройстве. Затем `GPUDevice.destroy()` запускает потерю реального устройства во время чтения. Проверяются очистка, статус и отказ последующих запросов. Сохраняется сценарий очереди из S3-S2D на восьми клетках при 3840×2160.

## P2-01 — отказоустойчивое освобождение GPU-ресурсов после независимого BLOCK

Каждый временный `GPUBuffer`/`GPUTexture` получает независимую попытку `destroy()`; исключение в одном ресурсе не отменяет уничтожение остальных и не вытесняет типизированный итог кадра отклонением Promise. Если входные пиксели прочитаны успешно, но cleanup выбросил исключение, результат — `failed/E_SESSION_GPU_FRAME`, не `rendered`. Если уже произошёл отказ readback, сохраняется его `failed/E_SESSION_GPU_READBACK`. Перед публикацией вызывающий код проверяет `stale`, `aborted` и подтверждённый `device-lost`; Canvas очищается только при актуальном `failed`.

Chromium negative tests дополнены инъекцией `GPUBuffer.destroy()` в реальном WebGPU/закреплённом WASM: совместно с отказом `mapAsync`, при успешном чтении, с проверкой попыток освобождения обоих буферов и обеих текстур, повторным успешным кадром и сценарием вытеснения старого отказавшего кадра новым. Это тест устойчивости к JS-обёрткам/инъекциям, а не утверждение о выбросах исключений стандартным нативным драйвером. Исходный [план Platform](https://github.com/netkeep80/fgm-platform/issues/15).
