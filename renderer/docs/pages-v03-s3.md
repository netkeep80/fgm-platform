## Отдельный линейный выпуск

В историческом выпуске V03 после авторского принятия публикационного PR и SHA-защищённого merge workflow `publish-v03-s3.yml` однократно запускался на изменение самого workflow в `main`. Он подготовил сохранённый снимок V03. Для восстановления сайта используется [текущий протокол отката](studio-pages.md). Исторический workflow выполнял следующие шаги:

1. Проверяет, что принятый merge V03-S3 — предок HEAD, затем выполняет негативные тесты публикационного скрипта.
2. Через API читает строго заданные run ID и artifact ID. Проверяет точный исходный SHA, SUCCESS, provenance и SHA-256 ZIP.
3. Проверяет список всех 18 записей ZIP, запрещает другие файлы, символьные ссылки, каталоговые подмены и повреждения. Для каждого из девяти файлов web/ проверяет отдельный SHA-256.
4. Извлекает только девять файлов браузерного пакета, добавляя пустую .nojekyll. Артефакты PPM/PNG, журналы тестов, исходники, закрытые игровые ресурсы и иные данные не публикуются.
5. Перед записью проверяет HEAD существующей ветки gh-pages = 063e2f8ace597ab1b4eddf0b535a36df56893595. Переносит проверенный пакет обычным fast-forward push без принудительного изменения истории. При дрейфе ветки прекращает выпуск.

Права workflow: contents:write и actions:read. Выпуск допускается только после push в main, не из pull_request. Нормативный кандидат FGMV-PUB-001 сохраняет статус accepted:false/current:false/published:false.

## Ограничение GitHub Pages и независимая приёмка

**Обычный push в gh-pages из GitHub Actions с GITHUB_TOKEN сам по себе не запускает Pages build/deploy** (см. официальную документацию GitHub). Поэтому успешная запись байтов в gh-pages означает только STAGED, а не DEPLOYED.

После staging требуется доверенный commit/push в gh-pages через GitHub App или пользователя, выполненный с проверкой актуального SHA и без изменения проверенного дерева. Затем следует отдельно проверить запуск Pages, загрузку HTML/WASM/JS по публичному адресу и браузерное управление камерой. Изменённая политика источника Pages может потребовать отдельной настройки репозитория; не объявлять публикацию состоявшейся только по green Actions.

Публичный сайт: https://netkeep80.github.io/fgm-renderer/ и https://netkeep80.github.io/fgm-renderer/camera.html. До подтверждения Pages deployment эти адреса не гарантируют новую версию.

## Критерии

- Сохранить старое демо сферы и добавить ссылку на синтетическую камеру карты.
- Обновлённый wasm содержит проверенную C++-камеру V03-S3; никакие оригинальные UFO/TFTD ресурсы, игровые кадры или закрытые данные не публикуются.
- Публикация статических файлов не доказывает аппаратную совместимость WebGPU, FPS/4K или игровой выбор по 3D-глубине.
- Независимый аудит exact HEAD/TREE, отдельное авторское принятие, protected merge, post-staging проверка дерева gh-pages и отдельный Pages deployment receipt обязательны.
