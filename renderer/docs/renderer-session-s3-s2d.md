# S3-S2D — ограничение чтения кадров WebGPU

Срез продолжает [S3-S2C](renderer-session-s3-s2c.md) и закрывает пункт P3-01 [план Platform](https://github.com/netkeep80/fgm-platform/issues/15) в границах одной сессии. Кандидат требования — [FGMV-SESSION-005](../../requirements/renderer/FGMV-SESSION-005.rg.yaml).

- За один раз WebGPU выделяет текстуры и буфер чтения для одного кадра. Пока ресурсы заняты, сессия хранит только последний ожидающий запрос. Вытеснённый запрос завершается со статусом `stale`, отменённый — `aborted`. При изменении сцены или вида и при уничтожении сессии ожидающий запрос освобождается. Перед выделением ресурсов и перед публикацией снова проверяется актуальность.
- Тест Chromium реконструирует связанную полосу 4×2 из восьми клеток закреплённым WASM. Отрисовка 3840×2160 проверяет геометрию и выделенную клетку. Для проверки очереди тест задерживает завершение первого реального чтения. Из четырёх запросов выполняются два чтения, одновременно доступно одно. Публикуется только последний кадр. Размер одного буфера чтения равен 33 177 600 байтам. Это размер выделенного буфера, а не замер общей видеопамяти.
- Журнал сообщает время одиночного кадра на SwiftShader. Оно зависит от машины и не является нормативом задержки игры. Подключение интерактивной Studio, классификация сбоев WebGPU и независимые эталоны перекрытий остаются отдельными этапами.

```sh
npx tsc -p runtime/tsconfig.json
node tests/renderer-session-wasm.browser.mjs build/pages-studio
```
