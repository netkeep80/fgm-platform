# V03-S1 — детерминированный CPU-контракт диметрической камеры

## Назначение и происхождение

Этот узкий срез задаёт математический контракт камеры для **одной локальной плитки** 16×16×24 в координатах R05. Владелец — `fgm-renderer`, нормативный кандидат — `FGMV-CAM-001`, задача — [план Platform](https://github.com/netkeep80/fgm-platform/issues/15). Принятые входные формулы и соглашения R05: [документация регенератора](https://github.com/netkeep80/fgm-platform/blob/main/regenerator/docs/r05-projection.md) и [`src/projection.cpp`](https://github.com/netkeep80/fgm-platform/blob/main/regenerator/src/projection.cpp).

Срез не изменяет FGM и не зависит от художественного профиля, GPU, масок коллизий, загрузки UFO или игровой видимости. Это математический фундамент будущих V03-S2 и V05, **не** полноценная интерактивная камера и **не** pixel-perfect raster произвольных 3D-мешей.

## Точный дискретный R05-профиль

Для клетки карты `(X,Y,Z)` и сдвига камеры `(cx,cy)` якорь в пикселях:

```text
anchor_x = 16 * (X - Y) + cx
anchor_y =  8 * (X + Y) - 24 * Z + cy
```

Локальная точка `(x,y,z)` удовлетворяет `0 ≤ x,y < 16`, `0 ≤ z < 24`. Для поворота `q∈{0,1,2,3}` вокруг центра локальной сетки (7.5,7.5) заменяем `(x,y)` на `(a,b)`:

```text
q=0: (a,b) = (x,y)
q=1: (a,b) = (15-y,x)
q=2: (a,b) = (15-x,15-y)
q=3: (a,b) = (y,15-x)

u = anchor_x + 16 + a - b
v = anchor_y + trunc_to_zero((40 + a + b - 2*z) / 2)
```

Вертикальное округление производится **после вычисления всего целого числителя** и к нулю даже для отрицательных нечётных чисел. Не подменять его `floor`, `round` или экранным антиалиасингом. Экран `u` растёт вправо, `v` — вниз. Повороты меняют только запрос камеры, не модель и не её SHA. Это ориентации внутри одной плитки; многоклеточный поворот вокруг центра карты — отдельный контракт.

## Отдельный непрерывный путь для обратного отображения

Для геометрического запроса с действительными координатами `(x,y,z)` экран вычисляется **без усечения**:

```text
u = anchor_x + 16 + a - b
v = anchor_y + 20 + (a+b)/2 - z
```

При **известной заданной высоте** `z` обратное преобразование вычисляет `d = u-anchor_x-16`, `s = 2*(v-anchor_y-20+z)`, затем `a=(s+d)/2`, `b=(s-d)/2` и обратную матрицу поворота. Выход за локальные границы возвращает `nullopt`; NaN, бесконечности, неверная ориентация или недопустимый z вызывают явный отказ.

Дискретный `raster_pixel` и `project_continuous` **не обязаны совпадать по дробной части пикселя**, особенно при отрицательных нечётных числителях. Из одних `u,v` без заданного `z` невозможно восстановить уникальную точку 3D. Обратная проекция на плоскость не подтверждает попадание в модель, тактическую проходимость или скрытые объекты.

## Проверка

Исполняемые исходники: `src/v03-camera.hpp` и `src/v03-camera.cpp`. Независимые формулы и фиксированные золотые координаты — `tests/v03-camera.test.cpp`. Сценарий запуска — `scripts/test-v03.mjs`:

```sh
node scripts/test-v03.mjs
```

Скрипт компилирует C++20 с `-Wall -Wextra -Werror -pedantic`, дважды исполняет проверку и требует тождественных выходных байтов. Результат `build/v03/report.json` содержит 24 576 R05-сэмплов в четырёх ориентациях, 24 576 непрерывных forward/inverse-пар, 6144 проверок четырёх поворотов, десять отрицательных случаев и SHA-256 входов/отчёта. В CI запускается до RepoGuard с отдельным ключом исполнения.
