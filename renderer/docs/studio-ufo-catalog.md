Сборка и provenance пакета берутся из единого Platform checkout: `docs/platform.md`. Старые инструкции отдельных source repos ниже являются исходным контекстом и не описывают текущую сборку; source-pinned workflow не запускается в Platform. Реальный текущий браузерный пакет проверяется root CI, публикация переносится отдельно на S07. На S08 устаревшие инструкции удаляются; архив истории не требуется.

# Выбор элементов UFO в Studio

Выберите локальную папку установки UFO: Enemy Unknown или X-COM: UFO Defense, затем карту и именованный тактический элемент. Studio показывает число его экземпляров и восстанавливает один представительный экземпляр. Известные типы имеют названия из каталога. Родовые названия пола, стен и объектов уточняются идентификатором набора и номером записи. Профили неизвестных карт и отсутствующие ресурсы видны при выборе карты.

Правила порядка наборов, классификация и разрешение индексов выполняются в [принятом WASM-исполнителе](https://github.com/netkeep80/fgm-platform/blob/main/regenerator/docs/studio-ufo-catalog.md). Индекс путей проверяется до отправки сообщения Worker с учётом полного JSON и UTF-8. Для выбранной карты браузер находит файлы по точным путям каталога и читает MAP и MCD один раз. Тот же снимок байтов передаётся инспекции и последующему R06. Набор спрайтов, банк палитры и параметры TAB берутся из каталога. Автоматический режим использует первый кадр и материал `stone`.

Значение элемента формируется из идентификатора карты, части клетки, набора, номера записи, признака правой половины кадра и координаты представительного экземпляра. Оно устойчиво при повторном выборе того же набора ресурсов. Выбор не записывается на диск. Смена папки, карты или элемента прерывает прежний запуск и сбрасывает результаты. Реконструкция и сравнение выполняются в браузере без сетевой отправки файлов.

Ручная привязка доступна через «Расширенную диагностику». Синтетический пример сохраняет обычный путь реконструкции. Проверки Chromium используют синтетическую папку и реальный Worker и охватывают идентификацию, выбор, реконструкцию, неизвестный профиль, нехватку ресурсов, повреждённую карту и смену папки во время инспекции.

## Локальная сборка

Команды выполняются из корня Platform после активации Emscripten 4.0.21. Все движки собираются из одного текущего checkout; engine-lock задаёт runtime contract, а Platform SHA/TREE вычисляются producer из этой сборки.

```sh
npm ci --ignore-scripts --no-audit --no-fund
emcmake cmake -S . -B build/wasm -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build/wasm --parallel 2
npm run build --workspace renderer
node renderer/scripts/build-studio-s2a.mjs build/wasm
npx playwright install chromium
(cd renderer && node --test tests/studio-r05.test.mjs tests/studio-ufo-catalog.test.mjs)
(cd renderer && node tests/studio-s2a.browser.mjs build/studio --catalog)
```

Проверяется настоящий локальный WASM Worker, исходные File API данные остаются в браузере. Общая автоматическая последовательность находится в `.github/workflows/platform.yml`; [текущая архитектура и сборка](../../docs/platform.md).


## Выпадающий список с оригинальными спрайтами (кандидат FGMV-STUDIO-004)

В разделе «Тактический элемент» используется combobox/listbox: **каждая раскрытая строка показывает настоящую 32×40 миниатюру слева от исходной подписи `Имя (DATASET № record)` ещё до выбора**. Это не preview реконструкции. Выбранный оригинал остаётся рядом с названием и в закрытом элементе управления; правые половины R05 явно подписаны и отображают только правые 16 столбцов. При порче PCK/TAB/палитры конкретная строка показывает исходный типизированный код отказа, а не безымянный значок.

Индекс текущей карты по-прежнему строится нативным `catalog-map`. Только при раскрытии списка клиент читает **из локальной выбранной папки** PCK/TAB/палитру для видимых строк и передаёт соответствующие MCD-байты уже проверенного снимка карты в отдельный краткоживущий WASM Worker. Команда `catalog-thumbnails` использует нативный R04, возвращает палитру и 32×40 индексов; JavaScript только преобразует эти индексы в RGBA на canvas, не повторяет PCK-декодер. Список виртуализован по 16 DOM-строк, обрабатывает не более восьми записей за пакет и ограничивает LRU 48 кадрами. Смена папки/карты/выбранной записи отменяет незавершённую работу и отбрасывает ответы прежнего поколения. Нет fetch к игре, CDN, постоянного кэша или сериализации игровых кадров.

Клавиатура: стрелки, Home/End, Enter/Space, Escape и Tab; ARIA combobox/listbox, selected/active, прокрутка и указатель/touch. Реальный браузерный тест синтетических независимых спрайтов проверяет пиксели красного, зелёного, синего, прозрачность, выбор до запуска R06, импорт, отказ испорченных оригиналов и позднюю отмену. При публикации сайт проверяется по HTTP SHA/TREE и показу оригинального кадра ещё до реконструкции. Девять существующих публичных Studio assets сохраняются.
