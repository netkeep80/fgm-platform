# Reconstruction Studio — целый составной объект (S3-S1)

## Назначение

Кандидатный пользовательский срез Renderer #38 после принятого S43-S2B и PR #39. Реконструкция целой конструкции идёт в **единственном принятом C++20 `BuildWholeObject`**, выполняемом из точного WASM Worker. JavaScript выполняет транспорт, проверку байтов, отображение общего OBJ и локальную выгрузку; отсутствует JS-дубликат канонического построителя или C05. Старый `r06-cell/1` и R05 сохраняются.

## Входы и доверие

Локальные `receipt.json` и `loft-0.json`…`loft-N.json` (N+1 от 2 до 8), ожидаемые SHA-256 из отдельного локального источника: JSON `{"receipt":"64 hex","lofts":["64 hex",...]}`, материал в границах ABI (до 48 ASCII). Пределы: каждый источник ≤64 КиБ, суммарно ≤256 КиБ. До первого `File.arrayBuffer()` проверяются количество файлов (receipt + 2–8 LOFT), точные имена, уникальность и непрерывность индексов LOFT, `File.size` каждого и их общая сумма. После чтения сохраняется повторная валидация длины фактических байтов. Отрицательные Chromium-тесты подтверждают ноль вызовов `arrayBuffer()` при неверных метаданных. Публичная синтетическая фикстура 2×2 с отверстием не использует игровые ресурсы. Исходные данные не уходят на сервер, не сохраняются в браузерном хранилище и не коммитятся в GitHub. Встроенный синтетический пример вычисляет SHA автоматически для теста, но это **не аттестация источника**.

SHA и `verified_explicit_membership` обеспечивают только заявленные транспортную целостность и проверку структуры. `input-proof.json` оставляет `reran_b1=false`, `rederived_r03=false`; протокол не подтверждает повторное B1 witness/R03 rederive из MAP/MCD/LOFTEMPS.

## API, результат и интерфейс

Команды Worker: `clear`, chunked `append`, `start(r06-whole-build/1)`, атомарный `step`, `finalize`, chunked `read-build`. Пять выходных файлов имеют описатели длины и SHA-256; скачивание доступно только после полной сверки всех файлов и схемы C05. Одна глобальная `preview.obj` отображается в диагностическом Canvas. Контуры клеток сохраняют игровую сетку, выбор `SliceByCell` лишь выделяет клетку и показывает её LOFT-слой, не производит независимую реконструкцию и не изменяет `model_sha256`.

Отмена во время вычисления прекращает весь Worker и запрещает stale replies; `step` не является инкрементальным. Другие ограничения: 2–8 клеток, одна TilePart/материал, статические LOFT, никакой автосклейки соседей, не полное 4-МиБ native envelope. Canvas не является единым будущим RendererSession/WebGPU.

## Приёмочные проверки

Правильность базового C++/WASM engine подтверждена upstream tests при pin Regenerator. Renderer PR должен дополнительно выполнить: packaged real-WASM whole-object demo 2×2, 4 клеточных среза, SHA отрицательный сценарий, cancel/stale, сохранение single-cell; Pages package allowlist/manifest; отдельный **публичный whole-object smoke после merge**. Нужны независимый adversarial аудит exact HEAD/TREE и отдельное авторское принятие; тесты сами не разрешают merge.
