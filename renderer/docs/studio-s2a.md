# STUDIO-S2A — реальный WASM-регенератор внутри браузера

## Состояние

Этот срез является **первым кандидатом** на единое приложение Reconstruction Studio. Он не заменяет опубликованную V03, не выполняет публичный Pages deployment и не изменяет исходные данные в приватном репозитории.

- Владелец: [план Platform](https://github.com/netkeep80/fgm-platform/issues/15).
- Архитектура: [план Platform](https://github.com/netkeep80/fgm-platform/issues/15).
- Единственный исполнитель R06: модуль [`regenerator/`](../../regenerator/) Platform; прежнее выделение в отдельный Git-репозиторий — исторический факт, не действующая зависимость.
- Закреплённый C05: `ba91a5e96d9f4f9580c9b2e9a9460b97acb7f01b`.
- Выходная геометрия: проверенный R06 OBJ, а не заново интерпретированная семантика FGM в JavaScript.

## Сценарий

Откройте локальную предпросмотровую сборку, выберите синтетический пример или явно загрузите файлы. Для оригинальных ресурсов требуется самостоятельно указать порядок MCD и привязку PCK/TAB к dataset, который поставляет выбранную часть MAP. Все выбранные файлы передаются только в локальный Worker через `postMessage`. Он исполняет C++20/WASM `r06-cell/1` согласно зафиксированному протоколу STUDIO-S1.

Команда `start` фиксирует входы, `step` атомарно проверяет 6144 центров, `finalize` отдаёт FGM, OBJ, отчёт и C05 proof. UI перепроверяет SHA-256 результатов средствами Web Crypto перед показом и экспортом. Неподдерживаемые связывания приводят к явному отказу.

Прерывание уничтожает Worker, а не изображает кооперативную отмену внутри атомарной операции. Прогресс передачи байтов реальный; у R06 пока нет промежуточных итераций, поэтому кнопки «Step/Pause/Resume» не подставлены фиктивным интерфейсом.

Рендерер пока показывает **диагностическую 3D-проекцию экспортированного OBJ**, без передачи исходной пиксельной формы в графическую подсистему. Визуальное сравнение оригинала с R05-калиброванным изображением, наложение, отличие силуэтов, Collision и полная интеграция V03 — отдельный следующий узкий срез STUDIO-S2B, необходимый до переключения Pages.

## Сборка и независимая проверка

Команды выполняются из корня Platform после активации Emscripten 4.0.21. Все движки собираются из одного текущего checkout; engine-lock задаёт runtime contract, а Platform SHA/TREE вычисляются producer из этой сборки.

```sh
npm ci --ignore-scripts --no-audit --no-fund
emcmake cmake -S . -B build/wasm -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build/wasm --parallel 2
npm run build --workspace renderer
node renderer/scripts/build-studio-s2a.mjs build/wasm
npx playwright install chromium
(cd renderer && node --test tests/studio-r05.test.mjs tests/studio-ufo-catalog.test.mjs)
(cd renderer && node tests/studio-s2a.browser.mjs build/studio --catalog)
```

Проверяется настоящий локальный WASM Worker, исходные File API данные остаются в браузере. Общая автоматическая последовательность находится в `.github/workflows/platform.yml`; [текущая архитектура и сборка](../../docs/platform.md).

## Информационные и функциональные границы

- Сайт не подключается к приватному `netkeep80/fgm-data`, не хранит токенов GitHub и не записывает локальные файлы автоматически.
- Нет аналитики, CDN, телеметрии, cookies, LocalStorage и IndexedDB для исходных данных.
- Свободный учебный объект является собственным синтетическим тестом, не содержимым UFO.
- Слишком большой набор входных файлов или несовпадающие привязки должны давать явный отказ. Суммарный лимит входов — 4 МиБ, максимум 21 файл.
- Реальные PCK/TAB могут быть структурно валидны, но относиться не к тому MCD. Не выдавать завершённый R06 за доказанную художественную идентичность.
- Публичная Studio выпускается единственным root workflow Platform после проверок текущего main.

## Приёмка

Для этого S2A: точный HEAD/TREE, успешно собранный принятый WASM, browser smoke на настоящем Worker, RepoGuard и независимый adversarial audit. Авторская приёмка после PASS — отдельным решением. Реальный исходный корпус остаётся вне публичного CI.
