# S02A — изолированная проверка сохранения Git-истории

Инструмент проверяет вариант миграции с сохранением исходных commit SHA. Для каждого модуля создаётся новый коммит с двумя родителями. Первый родитель продолжает Platform, второй указывает на закреплённый HEAD исходного проекта. Дерево модуля помещается под префиксом `core/`, `regenerator/` или `renderer/` с помощью `read-tree`. Исходные коммиты сохраняют прежние деревья и пути, новые деревья задают пространство имён платформы.

`docs/history-source-lock.json` фиксирует выбранные SHA/TREE из принятой карты источников. Проверяются все предки этих HEAD. Прочие ветки, самостоятельные теги и релизы требуют отдельного учёта перед реальным переносом. Внешний UFO Fractal остаётся отдельным потребителем.

## Воспроизведение

Требуются Python 3.10+ и Git с SHA-1 object format. Подготовьте полные локальные копии трёх исходных репозиториев и Platform, содержащие SHA из lock-файла. Рабочая ветка каждого входа может находиться на другом коммите.

```sh
python scripts/prove-history-migration.py --lock docs/history-source-lock.json --platform /path/to/platform --core /path/to/fgm-core --regenerator /path/to/fgm-regenerator --renderer /path/to/fgm-renderer --output /path/to/new-proof
```

Каталог результата должен отсутствовать. Инструмент создаёт в нём `proof.git` и `report.json`. На входных репозиториях выполняются операции чтения. Сетевые операции не требуются. Файлы исходных проектов в рабочий каталог Platform не копируются. При техническом отказе после создания результата каталог может содержать незавершённый эксперимент; повторный запуск выполняется с новым каталогом.

В `proof.git` ветка `history-proof` содержит три последовательных merge-коммита. У них фиксированные имя, адрес и дата автора эксперимента для сравнения повторных запусков. Метаданные исторических авторов и даты исходных коммитов сохраняются вместе с исходными объектами.

Для каждого шага проверяются точные родители, SHA поддерева и равенство остальных записей корневого дерева. Равенство дерева сохраняет байты, вложенные пути, исполняемые режимы, символические ссылки и gitlink-записи. Объединение множеств commit SHA сверяется со всей историей полученного HEAD, затем исполняется `git fsck --full --strict`. `source_commit_mapping` задаёт тождественное соответствие SHA для всех предков выбранных source HEAD. Хеш отсортированного списка и количество этих коммитов включены в отчёт.

## Проверки

```sh
python -m unittest discover -s tests -p test_history_migration.py -v
```

Синтетические проверки выполняются на Ubuntu и Windows. Они создают реальные Git DAG с merge-коммитами, двоичными файлами, исполняемыми режимами и символическими ссылками в Git index. Проверяются повторяемость результата, CLI, ошибочное TREE, shallow clone, коллизия префикса, дублирование модулей, существующий выходной каталог, переставленные родители и потеря файлов Platform. Тесты не требуют сетевого доступа.

## Следующая интеграция

После независимого аудита и приёмки инструмента последующие срезы переносят историю и требования. Исходные ссылки `implemented_by`/`verified_by`, пути сборки и автоматическая публикация должны быть согласованы с будущими префиксами. Результат S02A свидетельствует о сохранении Git-объектов в локальном эксперименте. Готовность native/WASM сборки и Web Studio проверяется при интеграции соответствующих модулей.
