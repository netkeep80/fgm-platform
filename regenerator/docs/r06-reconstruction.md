# R06-S1 — от статических вокселей к исполняемому пакету FGM

Срез строит локальную FGM-программу одной выбранной части клетки. Входы — факт LOFT из R03, индексный кадр из R04 и заданный способ сравнения R05. Пара R03/R04 должна относиться к одному набору и записи MCD. По имеющейся схеме скрипт проверяет совпадение номера записи. Связь набора обязан проверить вызывающий код, поскольку R04 не сохраняет идентификатор набора. Отчёт хранит метку набора, номер записи и SHA-256 обоих файлов с фактами.

## Запуск

Нужны CMake 3.24+, C++20 и Python 3. Интерпретатор FGM закреплён на принятом коммите [fgm-core](https://github.com/netkeep80/fgm-core/tree/ba91a5e96d9f4f9580c9b2e9a9460b97acb7f01b). Соберите проект обычным способом и передайте путь к собранному `fgmr-r06-sample`.

~~~sh
python scripts/reconstruct_r06.py --loft loft.json --sprite sprite.json \
  --part object --material stone --slot 0 --p-level 0 \
  --sampler build/fgmr-r06-sample --output reconstruction
~~~

`--slot` выбирает слот MCD 0–7. `--p-level` задаёт значение исходной записи из R02. При наличии западной стены в наблюдении северной сохраняется правая половина спрайта. Существующий выходной каталог сохраняется.

## Результаты

| Файл | Содержание |
| --- | --- |
| `model.fgm.json` | Канонический пакет FGM-0. Ячейки в единой локальной системе собираются в неперекрывающиеся блоки при обходе Z, Y, X. Блоки объединяются сбалансированным деревом `union`. Хеш отобранного семантического наблюдения и версия алгоритма участвуют в выводе семени. Камера, палитра и спрайт влияют на диагностику, а семантическая программа остаётся инвариантной к их изменению. |
| `report.json` | Происхождение входов, материал, объём проверки, число блоков и три счётчика R05 для сравнения силуэта. Уверенность в скрытой художественной поверхности отмечена `null`. |
| `preview.obj` | Сетка внешних граней занятых ячеек, повторно полученных выборкой FGM. Её можно открыть в просмотрщике OBJ. Общие внутренние грани удаляются. Для присутствующей части с пустой маской пакет содержит пустое поле, а OBJ остаётся без граней. |

Граница каждой ячейки имеет целочисленные координаты, выборка выполняется в центре. C++ интерпретатор проверяет **все 6 144 центра**, включая пустоту, и материал занятых ячеек. Сравнение использует точечную проекцию R05, фиксированный масштаб и исходный спрайтовый якорь. Оно сообщает расхождения. Геометрия сохраняет статическую игровую занятость, а художественная подгонка и исходные игровые ресурсы остаются за пределами проверки.

CTest строит MAP, MCD, LOFT, PCK, TAB и палитру плиты, арки с проёмом и асимметричного камня с нуля. Независимые ожидаемые формы проверяют количество занятых вокселей, силуэт и число внешних граней. Один лишний пиксель спрайта проверяет различение несовпадения. Повторный запуск должен давать те же байты всех результатов. CI публикует только результаты этих синтетических тестов.
