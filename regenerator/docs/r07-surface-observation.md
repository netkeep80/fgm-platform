# R07-S1A — непрерывная R05-проекция поверхности FGM (синтетический эксперимент)

**Статус:** кандидат требования `FGMR-R07-SURFACE-001`, `accepted:false/current:false/published:false`. Реализация по [Issue #52](https://github.com/netkeep80/fgm-regenerator/issues/52), не является завершённым подбором R07 и не подтверждает восстановление оригинального игрового объекта.

## Два разделённых наблюдения

Принятый R05 `projectLoft(tile, rows, camera)` остаётся без изменений. Он использует целочисленную проекцию 6144 дискретных проб и не служит целевой функцией изменения формы при фиксированном LOFT.

Новый отдельный native CLI `fgmr-r07-surface` интерпретирует переданный FGM-пакет **только принятым `fgm::Evaluator`**, перед любым изображением проверяет `sample_occupancy` (ровно 6144 центров, материал и полная таблица `Rows`) на точное равенство **переданной** эталонной таблице LOFT. Это проверка **относительно переданной таблицы**, а не самостоятельная аттестация её происхождения из игровых файлов. Идентичность исходного MAP/MCD/LOFT и ObjectDefinition должна подтверждаться отдельно на этапе S1B.

Для координат локального воксельного объёма `X,Y∈[0,16], Z∈[0,24]` непрерывная аффинная камера определена так:

```text
anchor = r05::tileAnchor(tile, camera_offset)
sx = anchor.x + 16 + X - Y
sy = anchor.y + 20 + (X+Y)/2 - Z
```

Ядро проекции — направление `(1,1,1)`. Каждый растровый пиксель проверяется по центральной точке `(sx+.5,sy+.5)`, с трассировкой луча в пределах клетки. Результат считается занятым при нахождении **хотя бы одной** точки с отрицательным полем принятого FGM-интерпретатора и запрошенным материалом. Для проверки луча используется ограниченный детерминированный шаг в локальных воксельных единицах (не более 1/8). Результат отсортирован по координатам и детерминирован.

**Важная математическая граница:** дискретный нормативный R05 использует C++ integer truncation, включая отрицательные половины; новый оператор — непрерывное аффинное отображение с выборкой **центров растровых пикселей**, а не побитовая замена `r05::voxelPixel`. Например, для локального целого `(1,0,23)` дискретная вертикальная координата равна `-2`, а непрерывная — `-2.5`. Калибровка якоря и translation инварианты проверяются отдельно.

`spriteAnchor` с `p_level` задаёт прямоугольное окно `32×40` для растеризации; `right_half=true` ограничивает его локальными `x=16..31`. `p_level` **не смещает** геометрию и не меняет `tileAnchor`. Глубина пересечений не публикуется: это бинарный силуэт, а не доказательство видимых/скрытых граней и не полноценный depth renderer.

## Протокол

Запуск: собрать native CMake и передать единственный JSON в stdin `fgmr-r07-surface`. Поля запроса строго фиксированы:

```json
{
  "schema": "fgmr-r07-surface-request/1",
  "package": "<локальная строка canonical FGM-package/1 JSON>",
  "package_sha256": "<SHA256 точных UTF-8 байтов строки package>",
  "reference_rows": "<массив из 384 беззнаковых 16-bit чисел, z*16+y>",
  "material": "stone",
  "tile": [0,0,0],
  "camera_offset": [0,0],
  "p_level": 0,
  "right_half": false
}
```

Это **описание структуры**, строки-заглушки не являются исполняемым JSON-примером. Таблица `reference_rows` должна быть удостоверена нативной R03/C05 и привязана к исходному source witness **до применения в S1B**. Не принимайте неподтверждённые строки, даже если native успешно сравнил их с FGM.

Выход — `fgmr-r07-surface-observation/1` в stdout: hash модели, hash переданной таблицы, C05 gate, координатный кадр, параметры камеры, `loft_mask_sha256`, `surface_mask_sha256`, массив `surface_pixels_xy`, счётчики лучей/проб и явная помета о неполноте. При ошибке — код выхода 2, только унифицированный локальный код в stderr, никакого успешного sidecar.

Ограничения: stdin до 128 КиБ, FGM package до 48 КиБ, размеры клетки фиксированы, смещения камеры `[-2048,2048]`, tile `[0,254]^3`, не более 1280 лучей / 200000 surface-probes. Пакет проверяется по SHA-256 **до** запуска FGM-интерпретатора. Результат содержит **UNRESOLVED_THIN_FEATURES**: алгоритм с конечным шагом может пропустить узкий компонент, полностью расположенный между пробами. Это принципиальное ограничение `r07-r05-center-rays/1`; измерить его можно, но утверждать топологическую полноту без отдельного адаптивного/интервального алгоритма нельзя.

## Независимый синтетический критерий

Две FGM-программы одной фиксированной структуры с центром куба `(8,8,12)` и half extent `3.51` против `4.49` имеют **идентичные центровые LOFT-маски (6144 проб)**: все координаты занятости попадают в `4.5..11.5` по X/Y и `8.5..15.5` по Z. Поэтому `ProjectLoft` обязана быть одинаковой.

Однако непрерывные поверхности имеют разные границы. Отдельный Python oracle решает пересечения луча с шестью аналитическими плоскостями куба, без вызова FGM/Evaluator/raster и без исходных игровых байтов. Для закреплённой камеры наблюдаются **148** и **244** растровых пикселя соответственно, XOR **96**. Тест подтверждает эти значения, в том числе обнаруживает мутант, подменяющий `surface_mask` неизменной `loft_mask`.

Дополнительно проверяются повторяемость, camera shift, якорь, отрицательная половина, правый полуспрайт, `p_level`, пустая геометрия, внутренняя полость, скрытая внешней поверхностью, и настоящий сквозной проём в тонкой панели (100 против 96 растровых пикселей, четыре пикселя отверстия). Отдельно проверяются неправильный SHA/Rows/границы. Linux и Windows CI исполняют настоящую C++20 сборку с этим оракулом.
