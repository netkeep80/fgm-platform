# STUDIO-S1 — восстановление одной клетки R06

Клиент передаёт байты выбранных локальных ресурсов одному Runner через native или WASM Worker. Движок проверяет MAP с упорядоченными MCD, разрешает статическую часть клетки через LOFTEMPS, выбирает кадр PCK/TAB и палитру и вычисляет сравнение силуэтов по R05. Произвольные пути и каталоги движок не открывает. Исходный порядок MCD и принадлежность комплекта PCK/TAB указывает вызывающая сторона.

## Передача и выполнение

Команды используют строковый протокол `v: 1` из [STUDIO-S0](studio-s0.md). `append` принимает логическое имя `file`, побайтовый `offset` и непустой `hex` в нижнем регистре. Разрешены последовательные порции до 32 КиБ на команду, до 21 файла и до 4 МиБ суммарно. `clear` очищает подготовленные входы. Эти команды доступны вне `RUNNING` и `PAUSED`. `start` завершает привязку и переносит все байты в неизменяемый снимок запуска. Имена файлов и наборов содержат до 48 букв ASCII, цифр, дефисов или подчёркиваний.

~~~json
{"v":1,"action":"start","spec":{"algorithm":"r06-cell/1","coreRevision":"ba91a5e96d9f4f9580c9b2e9a9460b97acb7f01b","budget":6144,"sourceBindings":{"map":"map","loft":"loft","datasets":[{"id":"BLANKS","file":"blanks"},{"id":"TERRAIN","file":"terrain"}],"sprite":{"dataset":"TERRAIN","pck":"pck","tab":"tab","palette":"palette"}},"parameters":{"tile":[0,0,0],"part":"object","material":"stone","frameSlot":0,"tabBits":16,"paletteIndex":0}}}
~~~

Требуются все объявленные файлы и точное соответствие подготовленных файлов привязкам. Для MCD используется только запись, разрешённая из выбранной части MAP. Нулевой MAP-индекс означает отсутствие части. Нулевой локальный MCD-индекс после разрешения порядка допустим. `sprite.dataset` должен совпасть с разрешённым набором. `P_Level` берётся из байта 49 той же записи. При наличии западной стены R05 использует правую половину спрайта северной стены. Клетка может иметь пустую маску занятости.

`step` атомарно выполняет реконструкцию и сверяет все 6144 центра с LOFT через закреплённый C05. `finalize` из `COMPLETED` возвращает четыре строки в `result`.

| Поле | Локальный файл |
| --- | --- |
| `model` | `model.fgm.json` |
| `preview` | `preview.obj` |
| `report` | `report.json` |
| `proof` | `viewer-proof.json` |

Модель использует канонический FGM-0 и детерминированное семя R06. OBJ формируется по границе проверенной занятости. Отчёт содержит разрешённую часть, кадр, исходный порядок и SHA-256 использованных байтов. Свидетельство C05 связывает SHA-256 модели, OBJ и отчёта. Схемы отчёта и свидетельства версионированы для S1. Перенос в пользовательский интерфейс относится к STUDIO-S2.

## Границы и проверка

MAP ограничен 64 КиБ, результат — 1024 боксами. Несовместимая привязка, недостающий файл, повреждённый ресурс или превышенный лимит завершают запуск явным кодом без исходных байтов в диагностике. WASM сохраняет ограничение S0 в 32 МиБ. Worker исполняется без удалённого API, а результат передаётся клиенту в ответ на `finalize`.

`tests/test_studio_cell.mjs` генерирует синтетические ресурсы, проверяет сохранение байтов FGM и OBJ по результату прежней команды R06 и сопоставляет полные ответы native с WASM Worker. На Linux тест дополнительно открывает тот же Worker в Chromium с локальной HTTP-страницы. Тестовый сервер принимает только запросы к синтетическим данным, странице и файлам движка. Публичные проверки и артефакты используют синтетические ресурсы.

Для проверки собственного оригинального набора запустите `node scripts/smoke_studio_cell.mjs build/fgmr-studio-native /путь/к/локальному/рецепту.json`. Рецепт содержит `files` со словарём «логическое имя → локальный путь» и `spec` из примера. Скрипт выводит только итоговый статус или код ошибки. Рецепт, исходники и восстановленные данные остаются локальными.
