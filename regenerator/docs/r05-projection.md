# R05-S1 — диметрическая проекция и сравнение масок

Версия камеры привязана к исходному холсту terrain 32×40. Экранные координаты растут вправо и вниз. API `fgmr-projection` работает в целых пикселях исходного холста, поэтому масштаб просмотра не входит в сравнение.

Для клетки карты `(X,Y,Z)` якорь равен `(16(X−Y), 8(X+Y)−24Z)` плюс пиксельное смещение камеры. Для мирового вокселя вычисляется клетка делением на `(16,16,24)` к нулю. Локальные остатки `(dx,dy,dz)` прибавляют `(16+dx−dy, trunc((40+dx+dy−2dz)/2))` к якорю. Усечение применяется после вычисления всего дробного слагаемого. [OpenXcom Camera](https://github.com/OpenXcom/OpenXcom/blob/4a4bae5fa2e5a09282928e84943fc84b093e34ff/src/Battlescape/Camera.cpp#L455-L484)

Для пола, западной и северной стен и объекта якорь спрайта сдвигается вверх на `P_Level`, хранимый без знака. При обычной отрисовке северной стены при наличии западной северная сохраняет только X от 16 до 31 исходного холста. API получает указание на этот режим от вызывающего кода. ## Сравнение

- `projectLoft` принимает клетку и статическую маску R03. Каждая занятая позиция даёт один пиксель. Совпавшие проекции схлопываются, координаты вне холста сохраняются.
- `spriteMask` принимает декодированный индексный растр 32×40 в порядке строк, положение клетки и исходный `P_Level`. Индекс ноль исключается из маски.
- `compare` выдаёт три счётчика. Это общие пиксели, пиксели только в проекции LOFT и пиксели только в наблюдаемом спрайте. Одинаковый перенос обеих масок оставляет счётчики прежними.

Точка вокселя задаёт диагностический образец. Площадь его грани, перспектива ручного спрайта и попиксельный порядок нескольких частей требуют отдельных моделей. Срез даёт локальную библиотеку и тестовые сцены. Сравнение работает на данных в памяти, а импорт ресурсов и выбор данных R03/R04 остаются у вызывающего кода. Публичные сцены создаются независимо.
