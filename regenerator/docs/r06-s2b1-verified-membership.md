# R06-S2B1 — проверяемый вход перед многоклеточной сборкой

## Область первого среза

Этап [план Platform](https://github.com/netkeep80/fgm-platform/issues/15) после принятого [план Platform](https://github.com/netkeep80/fgm-platform/issues/15) вводит отдельный локальный gate для состава экземпляра. **Единая FGM-модель, LOFT/C05, геометрические швы и native/WASM parity всей многоклеточной сборки ещё не реализуются в данном срезе.** Не изменяется семантика исходного декодера R02, прежнего R06 single-cell, формата FGM-0 и опубликованной Studio.

Граф S2A восстанавливается заново из локальных MAP/MCD и `entity-evidence-manifest-v1`. Нельзя принимать уже записанный JSON-граф из неизвестного происхождения как готовую истину. Только один выбранный `instance` с **explicit** membership допускается к локальному receipt. Соседство, общий MCD и гипотетические связи ничего не подтверждают.

## Исполняемый контракт

```sh
python scripts/verify_r06_membership.py \
  --facts-tool build/fgmr-r02 --r02-sha256 <локально_ранее_проверенный_SHA256> \
  --map local.MAP --mcd FIRST=first.MCD --mcd SECOND=second.MCD \
  --manifest local-evidence.json --witness local-membership.json \
  --frame-source local-frames.json --output local-verified-input.json
```

Файл `local-membership.json` — **отдельное свидетельство** с обязательными полями:
```json
{
  "schema": "fgm-regenerator/membership-witness-v1",
  "source": "independent-local-witness",
  "instance": "building-1", "prototype": "building-type",
  "anchor": [0, 0, 0],
  "members": [
    {"xyz":[0,0,0],"part":"object","dataset":"SECOND","record":0}
  ]
}
```

Идентификатор `source` должен отличаться от `assemblies[].source` исходного манифеста. Это предотвращает **формальное повторение одного source label**, однако само по себе не гарантирует независимость людей, достоверность ручного утверждения и лицензионные права. Пользователь обязан подготовить свидетельство на основании независимых фактов. Точное множество подтверждённых членов, instance, prototype, anchor, TilePart, MCD dataset/record и локальные координаты должны совпадать с заново построенным R02-графом. Состав из `hypothesis` или `unknown` блокируется. Никакого автоматического clustering.

`local-frames.json`:
```json
{
  "schema":"fgm-regenerator/frame-source-witness-v1",
  "inventories":[
    {"atlas":"terrain/SECOND","source":"terrain-atlas-index","frames":[0,1]}
  ]
}
```
Массив `inventories` сравнивается с локальной декларацией `frame_inventories` манифеста, а SHA-256 файла входит в receipt. Это **привязка декларации кадров**, не подтверждение наличия/правильности фактических пикселей PCK/TAB. Проверка атласа исходными ресурсами остаётся отдельной задачей.

Параметр `--r02-sha256` должен поступать из **независимого локального доверенного источника**, а не вычисляться автоматически из запускаемого файла в том же вызове. Исполняемые байты копируются в отдельный приватный временный каталог, SHA-256 рассчитывается **по записанной копии** и сверяется с ожидаемым значением; запускается именно `r02-pinned` / `r02-pinned.exe`, а не повторно открывается прежний путь. Замена или пересборка оригинала после копирования не изменит исполняемые проверенные байты. Проверка не гарантирует неизменность системных динамических библиотек, DLL или конфигурации окружения; такой внешний runtime зависит от платформы. Входные MAP/MCD также сверяются с хешами локального манифеста R06-S2A. Все входные пути, исходные байты и значения ошибок не копируются в публичный вывод.

## Безопасное исполнение

Применяются явные бюджеты: суммарно до 8 МиБ MAP/MCD; до 1 МиБ JSON-манифест и каждого из двух свидетельств; не более 17 источников MAP/MCD; R02 timeout 20 секунд; файл вывода R02 не более 48 МиБ; граф не более 150 000 узлов, 400 000 рёбер, 150 000 записей unknown и 32 МиБ сериализованного результата; подтверждённый состав до 4096 членов. При превышении — безопасный код отказа и отсутствие нового receipt.

Исходный R02-процесс выполняется с подавлением stderr и ограничением общего времени; родитель читает stdout через pipe с чанками до 64 КиБ. **Проверка размера выполняется ДО записи каждого чанка** во временный stdout-spool. Как только следующий чанк превысил бы 48 МиБ, дочерний R02 завершается принудительно и процесс reap; timeout также завершает и reap процесс. Поток вывода не может расширить spool выше бюджета в рамках одного локального процесса. `local-verified-input.json` формируется полностью во временном файле в целевой директории, затем публикуется через атомарное создание hard-link только если имя отсутствует. Существующий файл **никогда не заменяется**: конкурентная запись приводит к `E_S2B_OUTPUT_EXISTS`. Публикация требует файловую систему с поддержкой атомарного same-filesystem hard link (Linux и обычные Windows NTFS); иначе операция отказывает без создания нового receipt. Временные файлы удаляются. Абсолютной защиты от процессов с теми же правами, способных изменять каталоги/динамические библиотеки, контракт не заявляет.

## Выход

Локальный `fgm-regenerator/verified-membership-input-v1` содержит `instance`, `prototype`, `anchor_xyz`, отсортированные `cell_bindings` с `xyz,local_xyz,part,dataset,record,map_record` и `status=verified_explicit_membership`. В `provenance` записываются точные SHA-256 R02, карты, упорядоченных MCD, исходного манифеста, независимого свидетельства, объявления кадров и сформированного графа.

Схема — **кандидатный локальный выход** для следующего геометрического среза #37. Не выдавать её за нормативно принятую `FGMR-ENTITY-001` или `FGMR-ASSEMBLY-001`. Не загружать receipt, source-derived значения, исходные файлы или восстановленную графику в публичные PR/Issues/CI/Pages. Публичные тесты используют собственные синтетические файлы. Формальная аутентификация заявителя/подпись свидетельства пока не производится.

## Контроль

CTest `r06-entity-evidence` сохраняет прежние 20 сценариев и добавляет пять adversarial-тестов P2: контролируемый oversized stdout R02 с измерением фактических записанных байтов, timeout+reap, гонка внутри окна публикации, два конкурентных верификатора, замена исходного executable после pin. Тесты используют только собственные синтетические данные. Повторный запуск на идентичных файлах даёт те же байты. Приёмка: CI Ubuntu/Windows + RepoGuard + независимый exact HEAD/TREE adversarial audit + отдельное решение автора; публикация Studio не входит.
