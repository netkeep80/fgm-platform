# R04-S1 — исходные спрайтовые факты

Декодер читает пару terrain PCK/TAB, одну запись соответствующего MCD и выбранную исходную палитру. Результат содержит растры **32×40**, восемь ссылок на кадры, цветовые индексы, альфа-маску и палитру. Ориентация в JSON равна `null`. Кадры представляют анимационные слоты. Размер холста и рисунок сами по себе не определяют размер или форму LOFT.

## Формат

| Источник | Интерпретация |
| --- | --- |
| PCK | Первый байт пропускает строки. Литералы 0–253 дают индексы, 254 вводит длину прозрачного пробега, 255 завершает кадр. Запись идёт по строкам слева направо. Остаток холста имеет индекс 0. Прозрачные пробеги обрезаются по краю холста. Начальный пропуск за холст или любой литерал за холст вызывают ошибку. |
| TAB | Явный выбор ширины 16 или 32 бита, порядок little-endian. Смещения измеряются в байтах. Первое равно нулю. Каждое следующее строго больше предыдущего и находится внутри PCK. Интервал завершается ровно одним терминатором по правилам PCK, счётчик пробега может сам содержать 255. |
| MCD | Записи по 62 байта. Первые восемь байтов выбранной записи сохраняются в исходном порядке. Повторы и индекс 0 допустимы. |
| PALETTES.DAT | Банк из 256 троек RGB6 по смещению `index × 774`. Компонента RGB8 выводится как `RGB6 × 4`. Исходные значения доступны отдельно. Прозрачность равна 0 только при индексе 0, иначе равна 255. |

OpenXcom загружает terrain на холст 32×40. В его PCK-реализации таблица определяет число кадров, сами изображения читаются последовательно. Здесь TAB проверяется как таблица адресов, с диагностикой неполной таблицы, ошибочного диапазона, отсутствующего терминатора, переполнения холста и неверной ссылки. Срез ограничен плотно упакованными terrain-кадрами. Модифицированные игровые палитры, альтернативные схемы адресации и другие размеры холста требуют отдельной проверки. ## Запуск и проверка

После сборки CMake передайте соответствующие друг другу PCK, TAB и MCD. `--record` и `--palette-index` используют индексацию с нуля.

~~~text
fgmr-r04 --pck FILE --tab FILE --tab-bits 16 --palette FILE --palette-index 4 --mcd FILE --record 0
~~~

JSON на stdout использует схему `fgm-regenerator/sprite-facts-v1`. Массив `frames` перечисляет уникальные кадры в порядке первого появления в `mcd_frame_slots`. Каждый содержит начальное и конечное смещения в PCK и два построчных растра в hex. Проверяется весь PCK, включая кадры без ссылки из выбранной записи. При ошибке диагностика идёт в stderr, stdout пуст. Лимиты входов составляют 4 МиБ PCK, 64 КиБ TAB, 64 КиБ палитры и 1 МиБ MCD.

CTest строит файлы с нуля. Оракул задаёт цветные пиксели координатами и сравнивает весь индексный и альфа-растр. Проверяются оба размера TAB, прозрачный кадр, нулевой пробег, прозрачное дополнение в конце кадра и ошибки смещений, RLE, палитры и ссылок MCD. Оригинальные архивы используются только в локальных проверках со своим авторизованным доступом.

CI публикует `r04-comparison.png` только из встроенной в тест синтетической сцены. Верхний ряд показывает кадры декодера, нижний — эталон в тех же цветах и масштабе. Для локального вывода задайте `FGMR_R04_COMPARISON` с путём для PNG перед запуском теста.
