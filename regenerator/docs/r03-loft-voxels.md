# R03-S1 — статическая воксельная маска LOFTEMPS

## Назначение

Декодер R03 вычисляет **наблюдаемую статическую занятость тактической клетки** по собственным MAP/MCD/LOFTEMPS-файлам без художественных предположений. Результат не является треугольной поверхностью и не заменяет физический симулятор. Изменяющиеся двери, гравилифты, бойцы, отсутствие клетки и условия соседних клеток в R03-S1 **не моделируются**.

Владелец решения — [план Platform](https://github.com/netkeep80/fgm-platform/issues/15). Первичная формула и границы проверены по OpenXcom на коммите 4a4bae5fa2e5a09282928e84943fc84b093e34ff. Исходники используются только как спецификация через ссылки; копирования GPL-кода в Unlicense-репозиторий нет.

## Форматы и инварианты

[MapDataSet::loadLOFTEMPS](https://github.com/OpenXcom/OpenXcom/blob/4a4bae5fa2e5a09282928e84943fc84b093e34ff/src/Mod/MapDataSet.cpp#L275-L302) читает 16-битные строки little-endian, шестнадцать строк на профиль, то есть 32 байта. Значение MCD.LOFT[12] выбирает профиль для каждой пары соседних уровней высоты.

[TileEngine::voxelCheck](https://github.com/OpenXcom/OpenXcom/blob/4a4bae5fa2e5a09282928e84943fc84b093e34ff/src/Battlescape/TileEngine.cpp#L2525-L2582) задаёт:

- координаты одной клетки: X и Y от 0 до 15, Z от 0 до 23;
- индекс высотного слоя LOFT: целочисленное деление Z на 2;
- номер строки профиля: локальная координата Y;
- ориентацию бита X: номер 15 минус X;
- проверку занятости через логическое И между строкой профиля и одним битом;
- приоритет: пол, западная стена, северная стена, объект.

**LOFT ID 0 — настоящий индекс профиля 0**, не пустая часть. Только исходный байт MAP, равный нулю, означает отсутствие соответствующей части.

У каждого из четырёх источников сохраняются исходный глобальный MAP-индекс, ярлык MCD-набора, локальный индекс и двенадцать идентификаторов LOFT. Ярлык набора задаёт пользователь CLI и **не подтверждает происхождение данных**.

## Выходные данные

Команда `fgmr-r03` строит маску одной выбранной клетки из исходных MAP/MCD/LOFT. Данные JSON имеют схему `fgm-regenerator/loft-terrain-v1`:

- `part_rows[part][z][y]` — 16-битная маска строки каждой из четырёх частей в исходной битовой ориентации;
- `union_rows[z][y]` — побитовое объединение всех частей;
- `first_hit_rows[z][y]` — строка из шестнадцати символов в порядке X от 0 до 15: `F` пол, `W` западная стена, `N` северная стена, `O` объект, `.` пустота;
- `counts` — проверяемые числа занятой общей маски и масок отдельных частей;
- `sources` — идентификаторы ссылок MCD/LOFT в пределах переданных пользователем файлов;
- `sample` при выборе `--voxel` — первый попавший part и **все** совпавшие свидетели с полями `loft_id,row,bit,row_mask`. Внешняя локальная точка даёт `out_of_bounds` без чтения памяти.

Значения строк дают возможность диагностировать форму до появления браузерной сцены. Это **маска тактических препятствий**, а не художественный рендер.

## Запуск

Сборка через CMake и C++20. Пример для собственных локальных фикстур:

~~~powershell
cmake -S . -B build
cmake --build build --config Release
.\build\Release\fgmr-r03.exe --map "C:\fixtures\own.MAP" --mcd "ALPHA=C:\fixtures\alpha.MCD" --mcd "BETA=C:\fixtures\beta.MCD" --loft "C:\fixtures\loft.DAT" --tile "0,0,0" --voxel "0,0,0"
~~~

Возможен запуск под Linux с исполняемым файлом `build/fgmr-r03`. Вывод формируется только в stdout без записи на диск. Для игровых ресурсов вывод **не публиковать в GitHub**: он содержит геометрические факты, которые могут представлять производный материал.

Ограничения одного запуска: MAP не более 1 МиБ; MCD не более 1 МиБ на набор и 4 МиБ суммарно; LOFTEMPS — не более 256 профилей или 8192 байтов. Символьные ссылки на конечные файлы отклоняются; защита от конкурентной подмены родительских каталогов (TOCTOU) не заявляется.

## Испытания

`tests/test_r03.py` проверяет собственные паттерны LOFT с отдельным Python oracle для **всех 6144 локальных вокселей × четыре части**. Дополнительно проверяются объединение масок, первый попавший part, непустой LOFT ID 0, отражение X, крайние Y/Z, пары высот, последовательность MCD-наборов, ссылки, ошибки длины, отсутствующие профили, внешние координаты, повторяемость, предельный LOFT ID 255.

В Linux и Windows тесты запускаются вместе с принятыми R12/R01/R02. RepoGuard проверяет exact BASE/HEAD, русский язык документации и причинные связи требований.

## Границы результата

Этот срез подтверждает только **террейновую ветку LOFT на статичной одиночной клетке**. Оригинальный `voxelCheck` дополнительно зависит от состояния двери, юнита, гравилифта, наличия клетки и других условий игрового мира. Из полученной маски нельзя автоматически заключать, что готова универсальная система столкновений или трёхмерная художественная поверхность.

`FGMR-LOFT-001` остаётся кандидатом (`accepted:false/current:false/published:false`) до отдельного нормативного решения. Реальный пользовательский архив или приватный `fgm-data` не требуется ни для одного теста.
