# R07-S1B1B1B — локальный совместный подбор по исходным ресурсам

Подбор использует одну исходную модель из нативного `fgmr-r06-whole-build` и общий Δ. Входные манифесты описывают от двух до восьми разных наблюдаемых клеток одного проверенного B1. Для всех выбранных клеток сверяются точные MAP/LOFT-байты, порядок и SHA наборов MCD и материал. PCK, TAB и палитра привязаны к каждому манифесту отдельно.

Первый манифест должен совпадать с тем, по которому выпущен [S1B1A](r07-whole-source-preflight.md). Сценарий берёт внешние SHA-256 обоих receipt, повторно вызывает R03 для каждого члена B1 и восстанавливает S1B1A побайтно. Для каждой части 384 маски из нативного R03 одновременно питают сборщик R06 и проверку B0. Отчёт связывает SHA исходных строк 24×16 и их плоского представления, контроль сборки R06 и доказательства кадров Studio. C05 проверяет все клетки B1. Пиксельные метрики используют только клетки с непустыми наблюдениями R04/R05.

Пример запуска после сборки нативных программ. Используйте значения SHA-256, зафиксированные при подготовке исходных данных и исполняемых файлов.

```sh
python scripts/r07_whole_source_fit.py \
  --manifest private/first-selection.json \
  --manifest private/second-selection.json \
  --verified private/verified-membership.json --verified-sha256 "$B1_SHA" \
  --preflight private/preflight.json --preflight-sha256 "$PREFLIGHT_SHA" \
  --studio-native build/fgmr-studio-native --studio-sha256 "$STUDIO_SHA" \
  --r03-native build/fgmr-r03 --r03-sha256 "$R03_SHA" \
  --whole-build-native build/fgmr-r06-whole-build --whole-build-sha256 "$BUILDER_SHA" \
  --surface-native build/fgmr-r07-whole-surface --surface-sha256 "$SURFACE_SHA" \
  --output private/joint-fit
```

На Windows укажите пути к `.exe`. Результат сохраняется атомарно под новым именем каталога вместе с `whole-baseline.fgm.json`, `whole-candidate.fgm.json` и `joint-fit-receipt.json`. Если имя занято к моменту публикации, включая случай пустого каталога, запуск возвращает `E_B1_OUTPUT_EXISTS`. Для файловой системы без атомарного переименования с запретом замены запуск возвращает `E_B1_OUTPUT_ATOMIC_UNSUPPORTED`. Публикуйте в GitHub только согласованные сводные метрики. Все исходные байты, манифесты, модели и receipt хранятся локально.

`PARAMETERS_IMPROVED` требует измеренного улучшения при общем C05 и запрете поклеточного регресса. `UNRESOLVED_NO_IMPROVEMENT` фиксирует исходный вариант. При любом результате `stage_a=NOT_ACCEPTED`, а принадлежность целого объекта условна на достоверность внешнего B1-свидетельства. Для Stage A отдельно требуются измерение на оригинальных ресурсах, доказательство идентичности объекта, межклеточные перекрытия и новые контрольные 3D-ракурсы.

## Ограниченный поиск по осям

Параметр `--axis-fit` добавляет к скалярному поиску общие поправки полуразмеров по X, Y, Z и общие переносы по X, Y, Z. Каждая координата вектора выбирается из `{-0.49, 0, +0.49}` в единицах LOFT. Вектор применяется ко всем примитивам единого пакета. Поправки полуразмеров и переносы проверяются отдельными кандидатами относительно одной исходной модели.

Поиск проверяет 55 вариантов с учётом исходной модели. Сначала идут 5 скалярных вариантов, затем 24 поправки полуразмеров с неодинаковыми координатами и 26 ненулевых переносов. C05 применяется ко всем допустимым по диапазону кандидатам до вычисления IoU. Равенство метрик сохраняет ранее проверенный вариант. Режим публикует локальную схему `fgmr-r07-whole-source-fit-receipt/2` с полями `winner_transform` и `trace[].kind`. Значение `kind` определяет смысл `delta`: общий скаляр, вектор поправок полуразмеров или вектор переноса. Запуск без флага использует скалярную схему версии 1.

Проверка `r07-whole-source-preflight` включает сквозные сценарии на синтетических исходниках. Аналитическая маска записывается в PCK, затем проходит реальные R04/R05. Тесты проверяют общий скаляр, вектор поправок полуразмеров, перенос всей модели, улучшение двух наблюдений и 12 288 центров C05. Отрицательные случаи проверяют SHA предварительного receipt, расхождение с повторным вычислением R03 при совпадающем SHA файла и повторный выбор одной клетки. [план Platform](https://github.com/netkeep80/fgm-platform/issues/11)

Испытания P3-04 проверяют отказ от публикации при ошибке, тайм-ауте и повреждённом ответе native после настоящего успешного baseline. Два запуска по осям в каждом окружении CI должны дать побайтно одинаковые файлы. Независимый целочисленный расчёт проверяет порядок 55 вариантов, решение C05 и метрики для каждого допущенного варианта на синтетических боксах. Дополнительный бокс проверяет отклонение переноса, который меняет C05. Проверка прежней скалярной схемы сравнивает байты с принятым снимком #63, отдельно сверяя фактический SHA бинарника платформы.
