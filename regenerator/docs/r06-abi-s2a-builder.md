# R06-ABI-S2A — сборщик целого объекта на C++20

[Контракт и последовательность срезов](https://github.com/netkeep80/fgm-regenerator/issues/43#issuecomment-6918687291) · [Принятый Python B2](r06-s2b2-whole-object.md) · [Общий C05](r06-abi-s1-sampler.md)

Библиотека принимает байты локального свидетельства B1 и снимков R03, ожидаемые SHA-256 и идентификатор материала. Для каждого из 2–8 размещений она сверяет якорь, часть, запись MAP и запись MCD. Координаты LOFT переносятся в единый базис объекта. Из глобальной занятости строится одна FGM-программа с одним вкладом `whole_object`. Сборщик выполняет жадное объединение вокселей в блоки в порядке Z, Y, X с расширением по X, затем Y, затем Z.

Сэмплер из S43-S1 независимо вычисляет C05 в 6 144 центрах каждой выбранной клетки. Пакет и его производные возвращаются только при совпадении всех масок и материала занятых центров. Клеточные срезы используют проверенные LOFT-строки. Внешняя сетка генерируется из глобальной занятости с единым индексом для каждой координаты вершины. Общие внутренние грани исключаются.

## Граница проверки

Ожидаемые контрольные суммы поступают из доверенного локального источника отдельно от проверяемых файлов. Проверяются байты, структурные связи и соответствие C05. Первичное свидетельство членства проверяет B1, а происхождение R03 от MAP/MCD/LOFTEMPS устанавливается вне сборщика. Поля `reran_b1` и `rederived_r03` в `input-proof.json` сохраняют эту границу явно. `model_sha256` — SHA-256 байтов пакета, отдельный семантический хеш C04 требует принятого кодировщика домена.

На входе допускаются локальные координаты клеток от −16 до 16, одна часть на клетку, один материал из 1–80 допустимых ASCII-символов. Пределы составляют 1 МиБ на свидетельство и на каждый снимок R03, 8 192 блока и 4 МиБ на пакет. Результат следует хранить локально вместе с доказательствами при использовании ресурсов оригинальной игры.

## Локальный запуск

После сборки:

```sh
build/fgmr-r06-whole-build verified.json EXPECTED_B1_SHA stone output \
  loft-a.json EXPECTED_R03_A_SHA loft-b.json EXPECTED_R03_B_SHA
```

На Windows используйте соответствующий путь к `fgmr-r06-whole-build.exe`. В список можно добавить до восьми пар из снимка R03 и ожидаемого SHA-256. Порядок снимков произволен. Существующий выходной каталог сохраняется, а при ошибке в данных он не создаётся.

| Файл | Контракт |
| --- | --- |
| `model.fgm.json` | Пакет с той же канонической сериализацией и семенем, что у Python B2. |
| `slices.json` | Клеточные маски из одного общего объёма, сверенные через C05. |
| `preview.obj` | Внешняя поверхность с тем же порядком индексов и граней, что у Python B2. |
| `report.json` | Совместимый отчёт Python B2. |
| `input-proof.json` | Область проверки, SHA-256 свидетельства, снимков и пакета. |

Тест `r06-whole-build-native` запускает оба сборщика на одинаковых байтах. Он сравнивает четыре B2-артефакта побайтно на смежной паре, кольце 2×2 с проёмом и многоэтажном объекте с ненулевым якорем. Отрицательные проверки включают неверные SHA-256, изменённые привязки, лишний или дублирующийся снимок и дубликат ключа JSON.

Подключение к действиям Studio и проверка построения целого объекта в Chromium относятся к S43-S2B.
