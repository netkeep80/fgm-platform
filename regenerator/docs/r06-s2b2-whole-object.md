# R06-S2B2 — единый FGM-объём из подтверждённых нескольких клеток

## Связь с принятым R06-S2B1

В [Issue #37](https://github.com/netkeep80/fgm-regenerator/issues/37) после принятого [PR #41](https://github.com/netkeep80/fgm-regenerator/pull/41) начинается геометрическая сборка. Локальный B1 `verified-membership-input-v1` задаёт **достоверность явной привязки** экземпляра к клеткам. Срез B2 использует этот receipt, не выводит принадлежность по близости клеток или одинаковому MCD и не объединяет разные экземпляры.

Срез **кандидатный**, не нормативная реализация всех обязанностей #37. Здесь реализуется первое исполняемое многоклеточное ядро: одна FGM-программа, статические LOFT-маски из R03, независимая выборка C05 всего экземпляра, производные маски `SliceByCell` и визуальная поверхность без внутренних граней.

## Локальный запуск

Соберите CMake target `fgmr-r06-multicell-sample`. Предварительно локально получите B1 verified receipt и отдельный R03 JSON для **каждой клетки** выбранного объекта.

```sh
python scripts/assemble_r06_multicell.py \
  --verified local-verified-input.json \
  --verified-sha256 <независимо_зафиксированный_SHA256_байтов_receipt> \
  --loft first-tile-r03.json --loft second-tile-r03.json \
  --sampler build/fgmr-r06-multicell-sample \
  --sampler-sha256 <независимо_зафиксированный_SHA256_C05_executable> \
  --material stone --output local-whole-object
```

Одна команда создаёт **один** `model.fgm.json`, а не модель для каждой части. `generation.algorithm` задаёт `r06_multicell_loft_boxes` и версию `0.1.0`; `generation.resources` включает SHA-256 B1 receipt и хеш деклараций LOFT. Материал учитывается через `generation.resources.material_sha256` (SHA-256 его канонической строки), поскольку `fgm-core` допускает в `generation.parameters` только числа/числовые массивы. Различающиеся материалы поэтому имеют различные model seed, которые выводятся из canonical generation. Все воксели переходят в единую локальную систему относительно якоря B1: `(tile-anchor) * (16,16,24) + (x,y,z)`.

Учитываются только явно подтверждённые `cell_bindings`. Для каждой части проверяются `xyz`, `local_xyz`, `TilePart`, `dataset`, `record`, `map_record` (совпадение с R03 `tile.record_index` и `sources[].local_index`), уникальность тайла и отсутствие дублирующихся занятых позиций. Каждый предоставленный R03 JSON должен иметь фиксированные `voxel_dimensions_xyz=[16,16,24]`, `terrain_only=true`; все строки имеют ровно 24×16 корректных 16-битных масок. Файл R03 не может добавлять непроверенного соседа.

**Граница происхождения:** B2 проверяет SHA уже принятого локального B1 receipt, но не запускает заново B1; R03 JSON сравнивается по source binding, а не перепроверяется из исходных MAP/MCD/LOFTEMPS байтов. Подмена согласованной R03 маски оператором не распознаётся в этом срезе. Для строгой end-to-end привязки R03 executable и LOFTEMPS нужны следующие B2-срезы. Не считать B2 доказательством подлинности исходных игровых данных.

## Независимый C05 и SliceByCell

`fgmr-r06-multicell-sample` загружает **ровно один** пакет через канонический `fgm::Evaluator::from_package` и вызывает `sample_local` для всех 6144 центров **каждой** заявленной клетки. Проверяет также материал каждого занятого центра.

Перед вызовом C05 исполняемый файл копируется в приватный каталог и сверяется SHA-256 **на точных байтах копии** с отдельно предоставленным ожидаемым хешем. Запускается закреплённый C05, а не повторно открывается исходный executable path. Системные динамические библиотеки и доверенность значения ожидаемого SHA остаются ответственностью локального оператора. Python-сборщик независимо переводит исходные R03 строки в ожидаемые 6144-битные маски. Сэмплер выдаёт фактическую маску каждой клетки. **Любое несовпадение** блокирует публикацию результатов. После этого `slices.json` получает производные row-masks, рассчитанные из результатов C05; это не отдельные FGM-модели и не новая identity.

`preview.obj` вычисляется из общей occupancy-маски, так что соприкасающиеся воксели разных клеток не создают внутренние грани. Эта проверяемая статическая поверхность является геометрическим доказательством только на регулярной LOFT-сетке. Сложная художeственная поверхность, triangulation quality, rotations, non-axis-aligned instances, альтернативные материалы/перекрытия TileParts, подземные структуры и фрактализация сюда не входят.

## Ограничения начального вертикального среза

- Только **2–8 подтверждённых клеток** одного экземпляра, строго **одна TilePart в каждой клетке**; пустой объём не допускается. При совпадающих позициях voxels используется fail-closed, а не неявное объединение/сокрытие перекрытий.
- Один материал для общей FGM contribution, статические LOFT-0; локальные координаты клеток в диапазоне [-16,16] на каждой оси; до 8192 box-primitives и 4 МиБ model JSON. Динамические двери и единицы остаются вне области.
- Подпись B1 receipt не предусмотрена: ожидаемый SHA поступает от локального вызывающего кода. Исходные MAP/MCD/LOFT/PCK/TAB, результаты из них и receipt не коммитить в GitHub/Pages. Публичные тесты полностью синтетические.
- Нативный C05 CPU служит проверяющим; **WASM для новой глобальной геометрии ещё не реализован**. Существующие Studio native/WASM-regressions не доказывают новую parity.
- `output` должен отсутствовать до начала. Создание каталога эксклюзивно, но этот экспериментальный многoфайловый выход **не предоставляет атомарной публикации в случае падения процесса/питания**. Протокол B1 atomic receipt здесь не меняется.

## Синтетические тесты

`tests/test_r06_multicell.py` независимо определяет пространственные множества: 2×1 две соседние части одного тела, 2×2 кольцо с отверстием, вертикальный стык через Z, исключение постороннего соседа, неправильная SHA receipt/C05, подмена source binding R03, материал-зависимое seed и сохранение существующего output. Все три положительных случая проверяют точный C05 sampling, slices и количество граней глобальной поверхности; для двух соседних вокселей ожидается **10**, а не 12 граней.

После нового CI/RepoGuard требуется independent exact HEAD/TREE audit + авторская приёмка. `FGMR-ASSEMBLY-001` остаётся кандидатным требованием для отдельного нормативного рассмотрения.
