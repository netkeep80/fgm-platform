# STUDIO-S2B0 — пиксельные R05-наблюдения для Reconstruction Studio

## Назначение и границы

Этот документ описывает **кандидатное** расширение результата принятого `r06-cell/1`. Экранное сравнение Original/Reconstructed/Overlay/Difference/Collision требует точных координат и индексов, уже полученных исходными R04/R05 в C++/WASM. Перенос `r05::projectLoft` и `r05::spriteMask` в JavaScript запрещён. Веб-интерфейс может только отрисовать полученные координаты и данные палитры.

Владелец: [план Platform](https://github.com/netkeep80/fgm-platform/issues/15); потребитель: [план Platform](https://github.com/netkeep80/fgm-platform/issues/15). Старый V03 Pages не изменяется. Оригинальные байты и производные изображения могут быть получены только от явно выбранных локальных ресурсов, не попадают в публичные фикстуры и не передаются автоматически в сеть.

## Дополнительный локальный ответ

Только для `r06-cell/1` в `finalize.result` добавляется строка `visual` — сериализованный JSON с `schema: fgmr-studio-r05-observation/1`. Прежние четыре строки `model`, `preview`, `report`, `proof` сохраняют свои значения, кроме **дополнительного** поля `proof.r05_visual_sha256`. Хеши `model`/`preview`/`report` и канонический FGM не зависят от представления сравнения.

`visual` содержит `coordinate_frame: r05-ufo-dimetric/1`, исходную координату `tile`, рассчитанный R05 `tile_anchor`; для спрайта — `width:32`, `height:40`, полный набор 1280 индексов `indices_hex` из выбранного кадра, `palette_rgb8` из R04, `anchor`, `p_level`, `transparent_index:0` и `right_half`. При `right_half:true` семантика R05 рассматривает только правую половину исходного спрайта, сам массив индексов при этом не усечён.

Поля `predicted` и `observed` — массивы уникальных двухэлементных координат `[x,y]`, отсортированные нативным порядком `r05::Pixel` (сначала X, затем Y). Координаты **абсолютные в R05 frame при нулевом смещении камеры**, так что слои не требуется подгонять вручную. `predicted` — уже вычисленная R05-проекция проверенной C05 занятости; `observed` — уже вычисленная R05-проекция исходного выбранного кадра. `silhouette.common/predicted_only/observed_only` строго совпадают с принятым `report.silhouette`.

`proof.r05_visual_sha256` — SHA-256 ровно UTF-8 байтов строки `visual`; потребитель обязан проверить его до отображения. Существующий `proof.schema=fgmr-studio-c05-proof/1` остаётся прежним как совместимое аддитивное поле, для нового визуального режима digest обязателен. Допустимое отсутствие `visual` в старом принятом Runner означает отсутствие визуального контракта, а **не** право браузера вычислить маски самостоятельно.

## Приёмочные критерии

- Native/WASM byte parity всех ответов, включая `visual`; работа реального Worker в Chromium на свободной фикстуре.
- Нулевой MAP/пустая маска, исходные два состояния `right_half`, декодер R04, выбранный кадр и RGB8-палитра; совпадение пересечения/разности `predicted/observed` со счётчиками.
- Старые `model.fgm.json`, `preview.obj` и `report.json` не изменяют байты по причине визуального представления.
- Нет автоматических сетевых запросов, исходных ресурсов UFO в GitHub, публикации Pages, второго FGM/R05 интерпретатора.
- Requirement `FGMR-R05-OBS-001` остаётся `accepted:false/current:false/published:false` до авторского решения и независимого аудита.
