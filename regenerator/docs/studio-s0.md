# STUDIO-S0 — общее исполнение native и WASM

Протокол `v: 1` выполняет одну атомарную операцию `r06-occupancy/1`. Она использует общую с R06 проверку всех 6144 центров вокселей через C05. Пакет FGM разбирает закреплённый интерпретатор ядра. Тестовый контур S0 принимает один вклад с полем `program` и максимум восемью узлами.

Для побайтовой эквивалентности профиль S0 допускает `constant`, `parameter`, `box`, `translate`, `union`, `intersection`, `subtract` и `material`. Другое поле или операция дают `E_STUDIO_PROFILE`. В частности, сфера на границе занятости зависит от округления `std::hypot` в библиотеке платформы. Нативный интерфейс R06 по-прежнему использует весь набор операций C05.

## Команды

Каждая команда — строка JSON. Native принимает по команде на строку стандартного ввода. Модульный Worker принимает такую же строку через `postMessage` и отвечает строкой. Запрос `status` выдаёт начальное состояние `READY` и `runId: 0`.

Команда `start` требует объект `spec` с полями `algorithm`, `coreRevision`, `seed`, `budget`, `sourceBindings` и `parameters`. В `coreRevision` передаётся закреплённый коммит C05. Бюджет равен 6144 пробам. Единственная привязка имеет `role: "model"` и строку `bytes` с пакетом. Параметр `material` ожидает семантический материал. Движок сохраняет собственную копию привязки и перед вычислением проверяет совпадение `seed` с пакетом.

| Команда | Действие |
| --- | --- |
| `start` | Открыть новый запуск из `READY` или конечного состояния. Ответ содержит новый `runId` и `RUNNING`. |
| `pause` / `resume` | Перевести ожидающий запуск между `RUNNING` и `PAUSED`. |
| `cancel` | Из `RUNNING` или `PAUSED` перейти в `CANCELLED` и освободить вход. |
| `step` | Из `RUNNING` выполнить все пробы атомарно. Результат — `COMPLETED` или `FAILED`. |
| `finalize` | Из `COMPLETED` получить маску в порядке Z–Y–X, число занятых вокселей и число проб. Повтор возвращает те же байты. |

Команды после `start` адресуются по `runId`, кроме `status`. Запуск хранится до следующего `start`. Атомарная операция выполняется в Worker. Пауза и отмена применяются до неё, между сообщениями. Время исполнения не входит в семантический результат.

## Границы и проверка

Запрос ограничен 128 КиБ, пакет 32 КиБ, глубина JSON 32 уровня. WASM ограничен 32 МиБ линейной памяти. Ошибки запроса, версии, бюджета, привязки, лимита, состояния, модели, материала и памяти имеют коды `E_STUDIO_*`. Ответ с ошибкой не включает сырой ввод, пути или исходное исключение. Worker загружает сборку рядом со своим модулем. Рабочие команды не обращаются к сети и не сохраняются в браузерные хранилища.

На Linux сравниваются точные байты ответов native и WASM через отдельный Worker под Node. Оракул строит собственный FGM-бокс и независимо проверяет 6144 бита и 24 занятых вокселя. На Windows выполняется тот же оракул native. Публичные проверки используют синтетический пакет. Перенос выбора игровых файлов и сквозного восстановления R06 относится к STUDIO-S1.

~~~sh
cmake -S . -B build/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/native --parallel
emcmake cmake -S . -B build/wasm -DCMAKE_BUILD_TYPE=Release
cmake --build build/wasm --parallel
node tests/test_studio.mjs build/native/fgmr-studio-native build/wasm/worker.mjs
~~~

Команды WASM используют Emscripten 4.0.21. В папке WASM появляются `worker.mjs`, `fgmr-studio.mjs` и `fgmr-studio.wasm`. Клиент создаёт модульный Worker из `worker.mjs`, размещая три файла в одной папке.

Адаптер передаёт в `fgmr_studio_call(input, size, written)` адрес входа, длину UTF-8 в байтах и адрес 32-битного поля длины ответа. Возвращённый адрес принадлежит модулю и действителен до следующего вызова. Worker копирует ответ перед обработкой очередного сообщения. Сырые байты NUL в документе и повторяющиеся ключи отклоняются.
