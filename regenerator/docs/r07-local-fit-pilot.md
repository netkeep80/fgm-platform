# R07-S1B0 — локальный constrained-fit исходного наблюдения (кандидат)

**Узкий контракт:** [план Platform](https://github.com/netkeep80/fgm-platform/issues/11). Предшественники: R07-S0 PR #51, R07-S1A PR #53 — приняты и смержены. S1B0 **не** означает завершения R07-EARLY-MVP #50, восстановления настоящей ObjectDefinition, четыре контрольных ракурса либо Stage A acceptance.

## Архитектура

Вход — `fgmr-r07-local-selection/1` из принятого S0; он должен ссылаться на локальные MAP/MCD/PCK/TAB/LOFT/палитру с **ожидаемыми SHA-256** и на выбранный `tile/part/frameSlot/material`. Предварительно выбранный `object_key` — только локальное имя исследовательского образца.

1. Принятый `r07_local_observation` повторно читает и проверяет точные исходные байты по hash и запускает **нативный Studio Runner** для MAP/MCD source-binding, R04 frame decoding, R05 observed pixels и R06/C05 baseline. `verify_result` проверяет digest полученных файлов, identity исходной записи и 6144 центровых проб.
2. Тот же **проверенный снимок байтов** размещается во временном каталоге и передаётся в отдельный принятый `fgmr-r03`; `part_rows[z][y]`, `dataset/local-index/part` и `loft_ids` сверяются с S0. Нельзя заменить эту таблицу произвольным целевым JSON без source-binding.
3. `fgmr-r07-surface` получает baseline FGM-модель S0, таблицу R03, R05 tile и `p_level/right_half` из S0. Без успешного C05 равенства surface-mask не выдаётся.
4. Поиск использует **фиксированную грамматику**: уже принятые `extent_i` constant vec3 узлы боксов R06. Для каждого такого узла все три полуразмера меняются на одну общую добавку из `{-0.375,-0.25,-0.125,0,0.125,0.25,0.375}` локальных воксельных единиц. Seed, algorithm, parameters, baseline SHA пересчитываются; геометрический solver — **только принятый FGM Evaluator** через `fgmr-r07-surface`.
5. Каждый candidate **сначала** проходит полный native `C05(sample_occupancy)==R03 LOFT`, после чего по `P_surface` вычисляются IoU и симметричная контурная сумма Manhattan относительно **того самого исходного R04/R05 spriteMask**. Недопустимые кандидаты не ранжируются; `P_loft` между допустимыми неизменен.
6. Детерминированное сравнение: IoU с точным рациональным порядком (`common/union` без округления для выбора), затем contour L1; равенства параметров разрешаются порядком перебора. Нулевое улучшение — не PASS.

**Fail-closed правило P2-01:** отдельный кандидат исключается **только** при нативном завершении S1A с exit code `2`, пустым stdout и точным единственным stderr `R07-S1A: E_S1A_C05_LOFT_MISMATCH` (LF либо CRLF). В trace записывается `gate=C05_REJECTED` без вычисления loss. У baseline это исключение не допускается. Любое другое ненулевое завершение (включая аварийное), timeout, невалидный JSON, неверный SHA, некорректная схема/протокол или подмена этих маркеров **прерывают весь подбор с кодом 2, без каталога результата, receipt и статуса `UNRESOLVED_NO_IMPROVEMENT`**. Синтетические cross-platform fault-injection тесты подменяют ответ исполнителя только после успешного настоящего baseline.


`p_level` и `right_half` берутся из оригинального MCD/R05, не подбираются как свободные параметры. На одну попытку не больше семи кандидатов и максимум 48 КиБ на FGM-пакет по S1A. Это допустимая узкая область S1B0; модели вне неё считаются неохваченными, а не автоматически успешными.

## Выход и статус

`fgmr-r07-local-fit-pilot/1` сохраняется **только локально** вместе с исходным и подобранным каноническими `model*.fgm.json`, двумя private surface sidecars. В receipt присутствуют source и executable SHA-256, совпадение C05, hash исходного доказательства, таблица `loft_ids`, trace кандидатов/отказов, baseline/best IoU + contour, статус `LOCALLY_HASHED_NOT_INDEPENDENTLY_ATTESTED` для инструмента. Числа IoU и contour сами по себе не доказывают корректность скрытых поверхностей.

Допустимые конечные диагностические статусы:

- `PARAMETERS_IMPROVED_IDENTITY_UNRESOLVED`: модель действительно повысила IoU или улучшила контур на допустимом C05-множестве, но идентичность целого объекта не аттестована.
- `UNRESOLVED_NO_IMPROVEMENT`: допустимые кандидаты не улучшают начальную модель.
- Код отказа без receipt: некорректная подпись SHA, source-binding, нативный R03/Studio/Surface, превышение ограничений или недостоверный baseline.

**Ни один результат S1B0 не равен `StageAReceipt ACCEPTED`.** Даже `membership.status=explicit` в исходном селекторе не считается независимым доказательством завершённой ObjectDefinition. Для многоклеточного объекта, анимаций и персонажей нужны отдельные approved memberships/source graphs и совместный fit; для допущенных кандидатов недостаёт четырёх новых 3D видов, окклюзионного oracle и оценки тонких поверхностей.

## Запуск — исключительно на пользовательской машине

После штатной CMake-сборки:

```sh
python scripts/r07_local_fit.py \
  --manifest /PRIVATE/selection.json \
  --studio-native build/fgmr-studio-native \
  --r03-native build/fgmr-r03 \
  --surface-native build/fgmr-r07-surface \
  --output /PRIVATE/r07-fit-pilot-001
```

Для Windows используйте соответствующие `.exe` в `build/Release`. Перед запуском результат **не должен существовать**. Исходные пути и игровые байты в CLI output не включаются. Путь `/PRIVATE` — иллюстративный заполнитель. Нативные исполняемые файлы хешируются, но это **не** независимое подтверждение их происхождения/подлинности; запускайте только самостоятельно собранные и доверенные бинарники.

**Не публиковать** `selection.json`, PCK/TAB/MCD/MAP/LOFT/PALETTES, `model-*.fgm.json`, `surface-*.json` и полученные исходные/изменённые изображения/mesh. Публичная CI исполняет только **самостоятельно созданный синтетический набор** и независимый аналитический ray-box oracle. Все отчёты по реальной игре остаются offline/private.

## Следующие обязательные границы

S1B0 доказывает только возможность использовать исходное R04-наблюдение как функцию потерь для C05-допустимых параметрических FGM-кандидатов; фактическое улучшение оригинального объекта будет установлено **только после локального исполнения на удостоверенной ObjectDefinition**. Для S1B1 нужны объективный membership witness (включая все клетки и части), расширение грамматики без нарушения LOFT и четыре дополнительные R05/3D-проекции; для крупных пакетов — самостоятельный контракт расширения лимитов S1A. Если какой-либо gate не пройден, фиксировать `UNRESOLVED`, не создавать ложное свидетельство готовой модели.
