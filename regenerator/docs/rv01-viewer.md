# RV01-S1 — локальный Reconstruction Viewer / Studio

## Назначение

Первый интерактивный браузерный диагностический просмотр **реальных выходов R06/R07**. Веб-страница не получает права изменять FGM и не заменяет полноценный рендерер V03/V04/V05. Вся загрузка файлов выполняется только из выбранного пользователем каталога через File API. Не нужны сервер, облачный API, CDN, установка браузерного расширения или доступ к ресурсам UFO в публичном репозитории. WebGL2 требуется для рисования трёхмерной геометрии; при его отсутствии выводится диагностическая ошибка.

## Запуск для R06

1. Выполнить штатный `scripts/reconstruct_r06.py` и получить `model.fgm.json`, `preview.obj`, `report.json`, `viewer-proof.json` для плиты, арки или камня. Для готовых синтетических результатов возможно использовать локально сохранённые артефакты CI `r06-synthetic`.
2. Открыть `viewer/index.html` локально в Chromium, Firefox или другом современном браузере с WebGL2.
3. Нажать «Каталог R06 / RV01» и выбрать родительский каталог с вложенными папками объектов. Или выбрать файлы одного результата вручную.
4. Для режима **Collision** и сравнения **Original** положить в эту же папку исходные локальные `loft.json` и `sprite.json` из R03/R04. Просмотрщик сверяет их SHA-256 с `report.json` и идентичность части MCD; **без этих файлов он не подменяет LOFT геометрией OBJ**.

Обновлённый R06 генератор сохраняет `viewer-proof.json` только после C05/LOFT проверки: SHA-256 пакета, OBJ, отчёта, исходных LOFT и спрайта, версию диагностического профиля и базис координат. Browser дополнительно проверяет ограниченный структурный профиль R06 AST, вычисляет ожидаемую занятую сетку и побайтово воспроизводит OBJ из границ этих вокселей; это не общий исполнитель FGM. Старые R06-архивы без `viewer-proof.json` отклоняются — их необходимо регенерировать или перепроверить штатным R06. Публичные архивы R06 содержат геометрию и отчёт, но обычно **не содержат исходные sprite/LOFT**: требовать эти данные от пользователя без принудительного сетевого поиска. Источник проверяется отчётом и C05 в R06.

## Запуск для R07-S1

Сначала штатно выполнить R07-S1:

~~~sh
python scripts/run_r07.py --fit build/fgmr-r07-fit --output panel-fit
~~~

Затем построить **два** отдельных диагностических представления той же панели:

~~~sh
python scripts/export_rv01.py --source panel-fit --fit build/fgmr-r07-fit --output rv01-panel
~~~

`export_rv01.py` читает проверенный `panel.fgm.json`, `report.json` и все пять `*.pgm`. Из исходной фронтальной маски в `front.pgm` воспроизводится зафиксированное наблюдение. Для начальных параметров из `report.starts[0].initial` строится собственный канонический baseline. **Оба пакета отдельно передаются на штатную проверку `fgmr-r07-fit --verify`, использующую принятый C05**. Проверяется побайтовое совпадение итоговой FGM-программы с оригинальным `panel.fgm.json`. После этого по фиксированной форме `subtract(outer,opening)` строятся вторичные OBJ для обоих кандидатов. Это частный геометрический диагностический экспорт, **не второй семантический интерпретатор FGM**.

Открыть `viewer/index.html` и выбрать папку `rv01-panel`; браузер проверит SHA-256 обоих пакетов, OBJ, отчёта и всех пяти PGM-наблюдений, профиль/базис камеры, структуру FGM и параметр `opening_steps`, повторно сопоставит геометрию панели с параметрами и исходной фронтальной маской.

**P1-04 / согласованность трёх фронтальных масок.** При загрузке `front.pgm` Viewer разбирает все 96×32 пикселя, для фиксированного профиля `R07-synthetic-front` независимо воспроизводит бинарный фронтальный силуэт baseline из `report.starts[0].initial` и reconstructed из `report.fit` на тех же центрах пикселей и с теми же строгими границами, что `panel-fit.cpp`. После этого сверяются `mask_xor` и `contour_l1` с `report.starts[0].before/after`. Если любая из двух производных масок, её пиксели или численные метрики противоречат модели, Viewer **отказывает до активации новой сцены**. Хеш PGM в редактируемом манифесте не является доказательством семантической согласованности; два отдельных браузерных отрицательных теста меняют только baseline/reconstructed пиксель и пересчитывают хеш. Этот локальный аналитический oracle ограничен одной синтетической панелью и **не является вторым общим FGM-интерпретатором**.

## Возможности первого среза

- Свободное вращение мышью на 360°, приближение колёсиком, перенос камеры с Shift или правой кнопкой.
- Сброс исходного ракурса: для R06 непрерывная геометрическая ориентация R05, для R07 фронтальная ортография. Дополнительно четыре фиксированных вида: слева, справа, сзади, сверху.
- Выбор объектов, четыре 3D-режима Reconstructed / Baseline / Difference / Collision; Original — отдельная панель наблюдения, Free 3D — камера во всех режимах; если для выбранного объекта нет двух моделей, это **явно** отображается.
- Для R07 три изображения фронтальной маски на одной сетке: аналитический эталон, стартовая геометрия и результат. Сравнение 4 отложенных ракурсов находится в отчёте.
- Для R06 при наличии локальных исходных фактов: исходная маска alpha 32×40, исходная LOFT-проекция с координатами R05 и маска XOR. Геометрическая 3D-сетка является отдельным слоем.
- Два кандидата R07 одной панели: переключение видов меняет **реальные** геометрические данные, а Difference показывает два различных wireframe-слоя.
- Хеши исходных канонических FGM-пакетов проверяются при загрузке; камера, grid и режимы не выполняют запись в источник.

## Ограничения и открытые вопросы

1. 3D-кадр RV01 — **диагностическая ортография**, не нормативный пиксельный вывод R05. Для точного целочисленного сравнения сохраняется штатная библиотека R05; фронтальная синтетическая камера R07 не тождественна R05.
2. Выводимый из R07 OBJ представляет только фиксированную синтетическую панель. Другие типы программ не принимаются этим экспортёром; обобщённое извлечение поверхности — предмет будущей V05.
3. В RV01 новый R06-пакет сопровождается отдельным хешированным свидетельством и структурной проверкой канонической программы/занятости/OBJ. Это средство обнаружения противоречивых входов, **не криптографическая подпись доверенного издателя** и не заменяет штатную проверку C05 при выпуске модели. 3D-визуализация по OBJ не подтверждает достоверность невидимых поверхностей. Без face-level provenance пометка «гипотеза» задаётся на уровне модели. Для R06 неопределённость отмечена `null`.
4. Реальная эксплуатационная WebGL2-производительность, работа в нескольких браузерах и безопасность ручной загрузки файлов требуют независимой проверки на exact HEAD/TREE и авторского визуального принятия; CI Python-тесты не заменяют браузерный запуск.
5. Возможна неточность видимого наложения художественного спрайта из-за ручной авторской формы спрайта. Обязательно сохранять различие тактических LOFT-ограничений и визуального оригинала.
6. Для оригинальных/производных файлов UFO запрещена публикация в GitHub, Pages, CI и внешние сервисы. Синтетические объекты в CI созданы проектом.

## Трассируемость и линейный процесс

Источник архитектуры — [RV01 #26](https://github.com/netkeep80/fgm-regenerator/issues/26), предшествующая реализация — [R07-S1 #25](https://github.com/netkeep80/fgm-regenerator/pull/25), отдельная поздняя игровая камера — [V03](https://github.com/netkeep80/fgm-renderer/issues/7), будущий FGM Viewer — [V05](https://github.com/netkeep80/fgm-renderer/issues/9).

Кандидаты требований: `FGMR-VIEW-001`…`FGMR-VIEW-005`; жизненный цикл остаётся `accepted:false/current:false/published:false` до отдельного авторского принятия. Репозиторий продолжает использовать RepoGuard v6.0.1, независимый аудит exact HEAD/TREE и правило одного активного реализационного PR.

## Проверка в настоящем браузере

На Linux с установленным Chromium/Chrome можно выполнить:

~~~sh
python scripts/smoke_rv01.py --html viewer/index.html --browser-script viewer/rv01-browser-smoke.js --cdp-script scripts/rv01-cdp.mjs --r06-script scripts/reconstruct_r06.py --r06-test tests/test_r06.py --sampler build/fgmr-r06-sample --loft build/fgmr-r03 --sprite build/fgmr-r04 --r07-script scripts/run_r07.py --export scripts/export_rv01.py --fit build/fgmr-r07-fit
~~~

Команда запускает локальную страницу в headless WebGL2 (SwiftShader), создаёт четыре настоящие синтетические R06-сессии и пару R07, загружает их через File API, проверяет кадры WebGL2, четыре ракурса, drag/zoom/pan, пустую форму, отличие baseline/reconstructed и fail-closed отказы для подменённых FGM/OBJ/LOFT/PGM с пересчитанными индивидуальными хешами. Скрипт не обращается к сети. Данный smoke доказывает ограниченную работоспособность технической цепочки, **но не заменяет** ручной осмотр реальных R06/R07 объектов и точности 3D-наложений.

Headless smoke использует локальный DevTools Protocol через `127.0.0.1` (Node.js и установленный Chromium), ожидая завершение реального асинхронного File API по обычному времени, а не ускоренному virtual-time. Данный локальный канал не является публичной передачей ассетов.
