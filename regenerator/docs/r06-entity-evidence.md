# R06-S2A — доказательный граф исходных ресурсов

[Задача #36](https://github.com/netkeep80/fgm-regenerator/issues/36) · [Архитектура #35](https://github.com/netkeep80/fgm-regenerator/issues/35) · [Декодер R02](r02-map-mcd-facts.md)

Граф индексирует все занятые части одной исходной MAP и записи её упорядоченных MCD. Два размещения с одинаковой записью MCD имеют разные идентификаторы. Принадлежность к экземпляру устанавливается по явным свидетельствам. Фазы, состояния, направления, позы и конфигурации доступны как независимые признаки наблюдения. Выход S2A предназначен для последующей сборки объекта в [#37](https://github.com/netkeep80/fgm-regenerator/issues/37).

## Локальный запуск

После сборки `fgmr-r02`:

```sh
python scripts/build_r06_evidence.py --facts-tool build/fgmr-r02 \
  --map local.MAP --mcd first=first.MCD --mcd second=second.MCD \
  --manifest evidence.json > graph.json
```

На Windows с Visual Studio укажите `build/Release/fgmr-r02.exe`. `--mcd` задаётся в порядке исходных правил. Используйте локальные условные идентификаторы входов вместо имён, раскрывающих происхождение частного набора.

## Входной манифест

Обязательные поля `schema` (значение `fgm-regenerator/entity-evidence-manifest-v1`), `map` (`id`, `sha256`), `dataset_order_source` (идентификатор источника порядка) и `datasets` (упорядоченный список пар `id`, `sha256`). Контрольные суммы SHA-256 в нижнем регистре привязывают свидетельство к фактически декодированным байтам. Манифест готовят по независимому источнику, например по локальному `RuleTerrain`. Вывод R02 сам по себе не подтверждает правильность переданного ему порядка. Граф сравнивает снимки, он не аутентифицирует автора манифеста и не извлекает порядок из YAML.

| Необязательное поле | Структура и поведение |
| --- | --- |
| `assemblies` | Перечень записей `instance, prototype, anchor, source, evidence, members`. `anchor` — целочисленный `[x,y,z]` в системе данной MAP. Элемент `members` содержит `xyz, part, dataset, record` с ожидаемой точной локальной ссылкой. `explicit` подтверждает состав, `hypothesis` сохраняет версию группировки. Подтверждение обоих экземпляров для одной части считается ошибкой. |
| `frame_inventories` | Перечень `atlas, source, frames`. `atlas` имеет вид `terrain/<dataset>` или `actor/<sprite_sheet>`. Список отмечает индексы кадров, присутствие которых засвидетельствовано манифестом. При отсутствующем инвентаре или отсутствии кадра в нём доступность помечается в `unknown`. |
| `actors` | Записи `id` с необязательными `armor` и `observations`. В `armor` входят `source, sprite_sheet, drawing_routine, size`. Наблюдение содержит `id, source, parts` и может включать `camera_view, facing, time_phase, state, pose, configuration`. Направление `facing` находится в диапазоне 0–7. Порядок списка `parts` задаёт порядок слоёв. В слое обязательна `role`, необязательны `sprite_sheet, atlas_scope, frame, footprint_part`. Укажите `atlas_scope: "body"` для листа брони либо задайте `sprite_sheet` явно. Экипировка использует явно указанный атлас. Если лист не установлен, связь с кадром попадает в `unknown`. |

Ключи объектов проверяются, дубликаты JSON-ключей отклоняются. Идентификаторы начинаются с латинской буквы или цифры, далее допустимы латинские буквы, цифры, точка, дефис и подчёркивание (до 80 символов, для MCD действует ограничение R02). Привязка к экземпляру отклоняется при несовпадении ожидаемых координат, части клетки или ссылки MCD. После любой ошибки вывода графа нет.

## Формат графа

`fgm-regenerator/entity-evidence-graph-v1` содержит `nodes`, `edges` и список `unknown`. Рёбра адресуют узлы по идентификаторам, стабильным в пределах исходного снимка с теми же псевдонимами. `explicit` обозначает поле источника или явное свидетельство манифеста, `derived` — результат разрешения поля по известному правилу, `hypothesis` — предложенную группу. У записи в `unknown` поле `to` равно `null`, причина указана в `reason`. Все связи содержат `provenance` с идентификатором входа, точным локатором и версией декодера, схемы манифеста или ревизией OpenXcom. Принадлежность хранит `local_xyz` как разность координат размещения и якоря экземпляра.

`phase_state` обозначает визуальные состояния дверей НЛО. `next_phase` содержит событие `tick`, `open` либо `close` и при необходимости допустимые части клетки. `open_replacement_record` и `destroyed_as` адресуют MCD-записи, которые выбирают правила открытия и разрушения. Доступность пикселей отдельно от наличия ссылки на кадр, потому что граф работает с инвентарём, а не с PCK/TAB.

Выход сериализуется детерминированно для одинаковых входов. Пути, контрольные суммы и полные байты MAP/MCD в граф не попадают. Граф из игровых данных всё равно остаётся локальным, поскольку содержит производные факты. Публичные проверки используют самостоятельно созданные фикстуры без игровых ресурсов.

## Приёмка и трассируемость

Кандидат `FGMR-ENTITY-001` в [#36](https://github.com/netkeep80/fgm-regenerator/issues/36) связывает продуктовую цель с проверяемой принадлежностью и прослеживаемостью. Отдельное нормативное рассмотрение должно закрепить формулировку и связи RepoGuard. Для реализации проверочный артефакт — [синтетические тесты](../tests/test_r06_evidence.py).

| Проверяемое поведение | Свидетельство |
| --- | --- |
| Подтверждённый объект 2×2, независимые соседи и неизвестный состав при одном MCD | Двоичные MAP/MCD, локальный манифест и вручную заданная таблица ожидаемых подтверждённых связей |
| Остановка при перестановке наборов, несовпадении байтов и противоречивом подтверждении | Отрицательные тесты проверяют причину отказа и пустой stdout |
| Повтор кадров, временные переходы, состояния дверей, раздельные оси и слои актёра | Независимые проверки ожидаемых индексов, состояний, направления, фазы и порядка слоёв |
| Воспроизводимость, неизвестные связи и приватная привязка | Повторный запуск даёт те же байты; проверяются `unknown` и отсутствие локальных путей, полных записей и SHA-256 |
| Совместимость со статической клеткой | Штатные тесты `r06-reconstruction` и native Studio |

```sh
ctest --test-dir build --build-config Release -R r06-entity-evidence --output-on-failure
```
