# DR3-R0-B — исследовательский стенд B1, кандидат без результатов

Принятая [постановка R2](https://github.com/netkeep80/fgm-platform/issues/73#issuecomment-7170869338), [авторская приёмка](https://github.com/netkeep80/fgm-platform/issues/73#issuecomment-7171379063), [разрешение путей](https://github.com/netkeep80/fgm-platform/issues/73#issuecomment-7171522565). Только точечные пробы B1, B2/B3 — NOT_RUN. BASE 0dee9d0a5362d1ed17cd266208ec116fe5f11b0e. Рабочая реализация продукта не меняется. Начальный кандидат не утверждает B-G02 PASS. Семейства F01–F05 и независимый интерпретатор Fraction; корень для сферы допускается только при точном рациональном квадрате, не заявлена полнота общей численной выборки сфер. Сериализация ограниченного набора примеров не является полной реализацией JCS. Учитываются хеш исходного файла C04, канонические и доменные хеши, отдельно проверяется перестановка вкладов. Резолвер проверяет фиксированный дескриптор и хеш источника; предусмотрены отказы разрешения, выборки и бесконечный результат. Нет результата по лучам, GPU или производительности. P3-R0B-SCOPE-R2-01: B2 — не более 16 развёрнутых вхождений на вклад; B3 — обязательное нативное семейство из пяти параллелепипедов с отдельной областью millivoxel; предел импорта 128 не означает исследовательского покрытия, более крупные случаи NOT_RUN. Численный P3 этапа A0 остаётся отдельно открытым.

## Предварительная регистрация до измерений

На точном кандидате используются новые внешние каталоги. Зафиксировать компилятор, флаги, CMake, Python, точные хеши Core и зависимости (nlohmann 3.12.0 SHA256 4b92eb0c06d10683f7447ce9406cb97cd4b453be18d7279320f7b2f025c10187; непроверенная замена недопустима). Собрать корневой проект и отдельный потребитель без изменения продуктового CMake:
```sh
cmake -S . -B /tmp/r0b-root -DBUILD_TESTING=ON
cmake --build /tmp/r0b-root --config Release
cmake -S research/dr3-r0/r0-b -B /tmp/r0b-native -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/r0b-native --config Release
python research/dr3-r0/r0-b/run.py prepare --out /tmp/r0b-inputs
sha256sum /tmp/r0b-inputs/manifest.json /tmp/r0b-native/r0b_native_probe
```
Для Windows используются соответствующие внешние пути и исполняемый файл Release. До запуска опубликовать в #73 точные HEAD/TREE, окружение, команды и журналы сборки, хеши манифеста и двоичного файла. Проверить идентичность исходников, число примеров, точные ожидаемые исходы и коды ошибок; проверить недостающее покрытие постановки и дополнить до B1 PASS. Запускать только после отдельной контрольной записи:
```sh
python research/dr3-r0/r0-b/run.py execute --out /tmp/r0b-inputs --binary /tmp/r0b-native/r0b_native_probe --manifest-sha <exact> --binary-sha <exact> --receipt <issue-comment-id>
```
Результат записывается однократно, с исходным stdout/stderr каждой пробы. Контрольную запись проверяет оператор отдельно; параметр CLI служит для трассировки, а не сетевой авторизации. Автоматическое изменение допуска запрещено. Штатный CI необходим для контроля управления, но не подтверждает запуск отдельного стенда. B1 независимо проверяется до B2 и B3. До общего результата R0-B обязательны реестр 21/16 и мутанты R2. Кандидат не переводится в Ready до завершения, независимого аудита и отдельной авторской приёмки.

## Дополнение B1 после независимого аудита

Исходные 127 наблюдений сохранены без изменения. Дополнение F02 проверяет активную композицию бокса и перенесённой сферы, обрезку вторым боксом, вычитание сферы и асимметричные преобразования; пять различающих контрольных пар заданы до измерений. Дополнение F05 проверяет порядок конфликтующих ошибок узлов, обязательность вычисления обоих операндов трёх CSG-операций и различимые ошибки левого и правого операндов. Резолвер dual использует два явно заданных формата одного фиксированного синтетического источника: исключение и бесконечное значение. Нативный продуктовый Core не меняется. Все пробы остаются в ограниченной численной области. Повторно выполняются прежние и новые строки; отдельный манифест связывает дополнение с исторической регистрацией.

## B2a — начальный точный лучевой срез F01

Сохраняются исторические свидетельства B1 и независимый PASS. Дополнение не меняет алгоритм B1. Оракул Python исследует реальные соседние открытые ячейки глобального расположения опорных плоскостей; отдельный кандидат JavaScript использует рациональные BigInt-события и булевы знаковые секторы. Начальный класс: один экземпляр, единичное преобразование, один вклад, параллелепипеды. Применяются все опорные плоскости, включая продолжения, группировка равных событий и правило интервала на поверхности. Входы и исходники фиксируются до измерений. Команды: `python run.py b2-prepare --out <внешний-каталог>`, затем после отдельной регистрации `python run.py b2-measure --out <внешний-каталог> --manifest-sha <sha> --receipt <id>`. Это частичный результат ядра F01, а не закрытие B2: нативные точечные проверки новых пакетов, полная семантика экземпляров и материалов, адреса и разбиения, остальные семейства, алгебраические корни и мутанты остаются обязательными. Исторические манифесты B1 проверяются на их собственных точных ревизиях.
